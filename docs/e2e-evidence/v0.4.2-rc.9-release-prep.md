## 逐项修复

### P1 — 角标不再遮挡 time/actions

rc.8 的 `.devlead-row-mark-lead` 使用绝对定位 `top:1px/right:2px`，并以行级 `position:relative` 为定位上下文，
会覆盖同一行时间；触屏 `hover:none` 下还可能压住独立行操作。rc.9 删除行级定位规则及角标的
`position/top/right/z-index`，让角标成为 trailing seat 内 time 后的普通 inline-flex 子项。shell 的
resting/actions 两条布局轨仍由 shell 自己切换，插件不再把角标画到任一邻居上。

`styles.spec.ts` 不再固化旧坐标，改为禁止角标绝对/偏移定位及任何 Session-row 定位规则，并钉住 inline-flex。
真实 Chromium 在 lead 选中/未选中、light/dark 与实际拖到 264px 的窄侧栏中均测得 `position=static`、
time 在 badge 前且两个 DOMRect 不相交；hover/focus 时 resting 整体隐藏、actions 独立显示。
逐状态矩形见 [ui-verification](v0.4.2-rc.9-ui-verification.log)。

**触屏边界**：Browser MCP 没有 touch-emulation 命令，DevTools 快捷键尝试未改变 `hover:none=false` 的媒体事实，
因此本轮**没有声称完成触屏模拟或触屏实测 PASS**。触屏修复依据是生产 CSS 的非绝对 inline-flex 结构及 shell
分离的 resting/actions 轨道；桌面窄栏和 hover/focus 的真实几何不能冒充 touch 证据。

### P3 — hover/键盘 focus 下仍有 lead 说明

新增 `DevLeadSessionAccessibleMark`，在 `sidebar.session.row.leading` 仅为 active lead 渲染
`row.hover.enabled` 的 visually-hidden 文本；它不增加第二个可见标记，也不改 shell 行样式。trailing badge
被 shell `display:none` 时，leading 文本仍为 `display:block` + `clip:rect(0,0,0,0)`。真实 hover 下另有
hover card 可见说明；真实键盘 `inputModality=keyboard` + 行 `:focus-within` 下同样保留文本。
未运行操作系统读屏器，结论限于真实 DOM/ARIA/AX 文本、键盘和 computed style。

限制已写入 DESIGN/UI-VERIFICATION/release notes：高优先级 Session 状态点会替换 leading seat，此刻常驻
hidden lead 文本不可用，hover card 只是补充；blank 行和搜索结果行的既有 seat 限制不变。

独立 UI/UX 子复核 verdict = **PASS**（无 blocking、无需要返工的 concerns），覆盖可发现性、主流程、反馈、
视觉一致性、窄栏与上述验证边界。
