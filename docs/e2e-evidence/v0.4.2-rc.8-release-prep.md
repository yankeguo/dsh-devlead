## 根因与修复

基线普通四状态 fixture 已能通过，因此没有把“已有 blocked=1”误当作根因排除。独立 baseline repro
（真实 `useBoardFile → DevLeadBoardPanelView`）确定复现：一次自动 `stat` 永不 settle 后，非强制
single-flight 永久占住，watch 只累计 trailing、poll 直接返回；磁盘改为 blocked 后 UI 仍是旧 active
快照，KPI=0、refresh busy。对照正常 poll 通过，故障场景失败 `expected '0' to be '1'`。这证明一个相同
症状机制，不等于断言用户现场一定是 hung Remote。

`useWorkspaceFile` 现在给 stat/readBytes 组合加 10 秒 watchdog：超时先 error 收尾、再 abort 旧
controller；新触发看到 aborted single-flight 即可开启新 generation，不再依赖旧 Promise 的 `finally`。
正常响应仍清理 timer，path change/unmount 同步清理；旧响应继续由 generation/abort 检查丢弃。KPI、分组
和 banner 另统一由 `summarizeDevLeadBoardProjects` 派生，blockers 非空但 status 非 blocked 不计入 blocked。

自动化覆盖：精确 hung-stat 后卡片/KPI/revision 恢复、正常 poll、blocked 负控、KPI 与分组/banner 一致、
入口 icon/aria/gating、零值/强调、四态与 priority 解耦、lead 角标/非 lead/选中样式隔离、i18n、窄栏
键盘 strip 和样式 token。未改 Host 数据层、工具或 schema。
