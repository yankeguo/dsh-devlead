# v0.4.2-rc.1 发布准备：冻结树门禁与证据

本文件记录 **`0.4.2-rc.1` prerelease 候选**的发布准备门禁。基线：`main` = `f69bd21`
（远端同源，动态看板派生路径 + lead-only UI 已 push，版本仍 0.4.1）。本轮工作树在基线之上完成
P2/P3 收口与版本 bump（根 + 6 个可发布包 = `0.4.2-rc.1`），发布方式为 tag → CI staged publish
（`next`）→ 人工 approve → 手动 GitHub Release；**approve 永远由人类在 npmjs.com 网页完成**。

## P2/P3 收口内容

- **P2 冷 workspace 重建副作用**：派生路径（无 `boardPath` override）在 `start()` 前要求 lead
  记录的原始 workspace 根仍是**已存在目录**；缺失/非目录时看板以新 reason `missing-workspace`
  保持 disabled（`ctx.devLead.boardDisabledReason`），记录一条 warning，**不 `mkdir`、不写入**，
  工具返回 `BOARD_DISABLED`。显式 override 保持既有预创建语义（`0700`，不依赖 workspace 存在）。
  workspace 恢复后下一次 lead 同步/切换重新解析；`start()` 失败仍只降级
  （`boardStartError` + `BOARD_IO_ERROR`）。
- **P3.1** `packages/tool/README.md`（中英）更正「`devlead_board_read` 不读取身份」为 lead-only：
  调用者必须是当前 active lead，否则 `BOARD_DISABLED`；补充缺失 workspace / 无 workspace 的
  禁用条件。
- **P3.2** `docs/UI-VERIFICATION.md` 的 64 KiB 描述改为「工具层 `devlead_board_read` 上限」；
  右栏面板直接读文件（schema 256 KiB 上限），不经工具层裁剪。
- **P3.3** 右栏恢复的 board tab 在「当前 on-screen Session 已非 lead / surfaces 从未注册」时
  不再残留：初始 sync 与插件 cleanup 都做一次 best-effort `closeBoardTabs()`；补 render-free
  单测（initial sync / plugin dispose 两条路径）。
- **P3.4** `boardStartError` 在同路径分支按需重试：同一 resolved 路径的下一次 lead 同步在
  degraded 时重试 `start()`，成功则清空错误、失败则保留；补同路径重试用例。
- **P3.5（低风险子集）** watcher 释放单测（`close()` 后 watcher close 且不再 rearm）、
  `docs/BOARD.md` 冷 workspace / 重试 / `boardDisabledReason` 文案、`packages/client-ui/README.md`
  补空态有界轮询 / 共享 schema / 直接读文件 / 恢复 tab 关闭说明、board 工具描述与
  `resolveDevLeadBoardPath` / `DevLeadBoardStore.start()` 注释措辞。
  未做（明确留待后续，不影响本版）：`leadWorkspaceRoots` 清理上限、protocol `zod`
  peer 改 optional。
