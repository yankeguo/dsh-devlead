# v0.4.1 — 旧事件日志的 supervisor 扫描恢复

0.4.1 是 **0.4.0 的补丁版**，交付 `462740f`（`fix(devlead): recover supervisor scans from legacy events`）中的正确性修复。**没有公网 API 变更**：不新增或改名模型工具，不改变工具参数、错误码、projection 契约或 DSH 兼容面；`engines.dsh` 仍为 `>=0.2.2-rc.1 <0.3.0`。

## 修复内容

此前，某个 Session 的 v4 JSONL 日志即使物理完好，只要含有**旧插件写入、当前 Harness 不认识且未标记 `ignorable`** 的事件，Host 的 `readSession` 就会拒绝重放整份日志。DevLead 因而无法证明完整的 supervisor 集合，对既有 Session 的 `devlead_prompt_session` 会持续以 `DEVLEAD_SESSION_UNAVAILABLE` 拒绝投递，普通重试无法恢复。

0.4.1 只对这一种精确的 Host 拒绝错误启用**有界、只读的当前 v4 JSONL 恢复**：

- 通过已组合的持久化服务取得并确认后端元数据中的绝对 JSONL 路径，不相信错误字符串或调用方提供的路径；
- 支持当前 `session.v4.jsonl[.zstd]`，读取并保留全部完整记录，校验物理 envelope、连续序号与 fork inherited cut；
- 不解释无关旧事件的 payload，所有 DevLead 记录仍经过原有严格 projection fold；
- 其它读取失败、格式损坏、非当前格式、日志在读期间变化或 DevLead 记录损坏，仍然 **fail closed**，不会借此获得 prompt 授权。

## 安全性与可诊断性

- **不修改、不截断、不删除日志**，不发布或 resume 用户 Session；恢复仅服务于 DevLead 的只读 supervisor 扫描。
- **不忽略损坏的 DevLead 记录**，不放松 Host 全局单活 lead、`DEVLEAD_FOREIGN_SUPERVISOR` / `DEVLEAD_MULTIPLE_SUPERVISORS` 或防跨 lead 劫持语义。
- 错误信息现在给出具体 **Session id、日志路径与原因**；临时 I/O、listing、timeout 与 torn-tail 场景走有界自动重试，原始存储/格式问题与需要修复的损坏 DevLead 记录分别给出处理指引。不要仅为绕过检查而删除日志。

## 升级建议

0.4.1 之前的版本遇到上述旧日志时会拒绝投递，建议升级到 0.4.1。**从 0.4.0 升级后无需清理日志，也无需为此修复执行 `/devlead reset`**；临时故障清除或只读恢复成功后，有界探针会继续恢复扫描。

从低于 0.4.0 的版本直接升级时，0.4.0 已有的 record v2 / outbox v3 等 breaking 升级注意事项仍然适用，详见 [v0.4.0 release notes](v0.4.0.md) 与 [COMPATIBILITY](../COMPATIBILITY.md)。

## English summary

v0.4.1 is a patch release with no public API changes. It adds a bounded, read-only recovery path for physically healthy current v4 JSONL Session logs rejected solely because an old plugin wrote an unknown, non-ignorable event. The recovery uses backend-verified paths, preserves every complete record, keeps strict DevLead folding and fail-closed single-supervisor admission, and never edits or deletes logs. It also improves Session/path/cause diagnostics. Upgrading from 0.4.0 requires no log cleanup or `/devlead reset` for this fix.
