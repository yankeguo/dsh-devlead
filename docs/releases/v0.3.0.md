## Workspace 三寻址

- `workspace` 参数接受 **id / 注册目录路径 / 精确 display title**（trim 后大小写敏感）；
  解析顺序 id → 路径 → title。同 title 命中多个 Workspace 时报
  `DEVLEAD_WORKSPACE_AMBIGUOUS` 并列出候选 id/path，不猜。

## 显式打断（`devlead_prompt_session interrupt`）

- `interrupt: true` 经 `workspace/session-stop` providers 停止运行中的 turn 与
  subagent/job/schedule 工作、丢弃排队输入，再投递替换 prompt；idle/cold 目标是 no-op。
  被中断的 turn 仍产生 watched 通知（显示 cancelled）。
- stop 已提交后若 `followup` 失败，**保留本次新增的 watch**（不补偿），错误文案提示重试，
  避免把已停止的子会话留在无人关注状态。

## watched 子会话问题路由

- 硬性 `tools/pre-execute` 闸门：watched 非 lead 子会话的 `ask_user_question` 在其问题 UI
  运行前被拒绝，格式化为 durable `kind: question` report 转给 active lead，子会话被要求
  结束 turn 等 lead 用 `devlead_prompt_session` 回答。当前 turn 由人类直接发起的子会话放行。
- `DevLeadReportKind` 新增 `question`；question 报告**不计入**每轮 4 条普通报告预算。
  转发失败退化为「结束 turn 并在最终 assistant 消息里写明问题」。不新增错误码。

## 排队 inbox 输入：可见 / 可撤 / interrupt 保留策略（新）

- `devlead_get_session` 在目标 live 时附带 `queuedInputs`：每条排队消息的稳定 id、boundary
  （next-turn/next-step）、来源 kind/form/sender、≤240 码点文本摘要、入队时间（从 durable
  `agent/inbox/spliced` 日志反查）。冷会话省略字段，不谎报空队列。
- **新工具 `devlead_retract_input(session, input_id)`**：在执行前撤回一条排队输入；仅限
  本 lead 自投的 relay prompt（人类/scheduled/其他来源拒绝并文案说明），幂等（已消费/已撤回
  → `retracted: false`），目标须 live 且非 lead 自身。错误码复用现有词表。
- `devlead_prompt_session` 新增 `interrupt_inbox`（默认 `clear-all` 即历史行为；`keep`
  恢复全部排队输入、`clear-own` 恢复除本 lead 自投 relay 外的全部）。Host stop provider
  固定清队列，保留实现为「停止前快照 → 照常 stop → 以原 id/原 boundary 恢复」，恢复消息按
  原队列顺序排在替换 prompt 之前；结果新增 `retainedInputs`。abort 后驱动循环不可能 claim
  恢复的消息（rc.1–rc.5 的 Inbox 按条 API 与稳定消息 id 均已核对）。

## 全面审计修复（工具面与代码质量）

- **4 个核心 P0**：跨 kind 同文 question 被 progress 去重吞没（幂等键改为 kind+message）；
  无 source 的 inbox 消息致 flush 未处理拒绝；dispose 不 await outbox.close 致重载撞
  storageDomain 单开、durable 报告静默降级；interrupt 已停后 followup 失败误回滚 watch。
- **工具面零契约变更**：描述按官方 tool-design 准则去重（总字符 10298 → 8613），参数补
  `default` schema 注解，6 个只读工具声明 `isConcurrencySafe`，report kind 枚举改从
  `DEVLEAD_REPORT_KINDS` 单一来源派生，披露 notifications limit 双 digest 作用与自读 5 条上限。
- **report 指引收窄**：turn 结束自带通知，`devlead_report` 只用于长任务途中关键节点
  （真实阻塞/需 lead 决策的分叉/等待会影响调度正确性的进展/提问），常规进度与最终总结不
  重复播报，短任务/线性任务默认不调用。
- command/protocol：archived 标题单行折叠、idle 队列显示、反向引号/零宽粘贴诊断、裸 uuid
  头本地匹配、wire-drift 防御、reset 词表钉死。
- client-ui：report 详情改中性色（error 红保留给 turn 失败摘录）、唤醒文案补 report/question
  通道、admission 在途竞态、行标记 O(N²) → 快照缓存、原型键防御、paint-inset fallback。
