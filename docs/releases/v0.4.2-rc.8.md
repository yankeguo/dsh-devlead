# v0.4.2-rc.8 — 看板可读性、lead 角标与自动刷新恢复（prerelease，dist-tag `next`）

`0.4.2-rc.8` 是计划中的 `0.4.2` 补丁版的候选，基于已发布的 `0.4.2-rc.7`。本候选只改变
client-ui，不改 Host 数据层、工具、board/notes schema、Remote 或 DSH 兼容面；**不是稳定版**。

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.2-rc.8
```

## 变化

- **看板入口**：会话头部与 guide 统一使用 18px 仪表盘图标，按钮保持 28×28；本地化
  tooltip/aria-label 和 lead-only gating 不变。
- **KPI**：固定 blocked → active → paused → done 的单行 pill strip，增加状态图标；零值中性、
  blocked>0 才强 warning，revision/updated/Live 保留。极窄栏可横向滚动，strip 可键盘聚焦。
  KPI、项目分组与 blocked banner 由 `summarizeDevLeadBoardProjects` 从同一份 groups 派生。
- **blocked 计数恢复**：确定复现一次自动 `stat`/`readBytes` 永不 settle 时，single-flight 会永久
  阻止 watch trailing 与后续 poll，磁盘已 blocked 而 UI 仍保留旧 active/KPI=0。现在每次读取有
  10 秒 watchdog：超时先完成 error 收尾再 abort 旧 controller，后续自动触发可开启新 generation；
  不依赖旧 Promise 的 `finally` 才恢复。没有用户现场 trace，因此不把所有同类反馈都断言为 hung Remote。
- **卡片颜色与边框**：四态均使用完整四边边框和轻底色，移除 priority 驱动的单左边色条。status
  唯一决定卡片基色：active=business、blocked=warning、paused=neutral、done=success；priority
  只保留独立 badge。blocked KPI/banner/卡片共用 warning token。
- **侧栏 lead 角标**：移除 active lead 的整行四边 overlay ring，改为右上角 sparkle + `LEAD`
  小角标，带中英文 aria-label/title。shell 的选中、hover、focus、行盒和背景不变；非 lead 无角标，
  watched 准星保持弱化。
- rc.7 的原生 notes 编辑、index CAS、live reader 与 rc.6 的主动 board workflow 保留。

## 自动化与真实窗口证据

- `pnpm install --frozen-lockfile`、`pnpm run verify`（53 个测试文件 / 1857 项测试，6 个构建目标）、
  `pnpm run check:packages` 均通过。
- 三条真实 DSH `0.2.2-rc.5` E2E：patch / installed 各 244/244（241 PASS + 3 个既有无凭据
  模型选择 SKIP），patch `--no-worktree` 220/220（217 PASS + 3 SKIP）。
- 6 包 `stage-release --dry-run --dist-tag next` 全绿，没有上传或创建 stage id。
- 三组 mutation 均被测试杀死：blocked 计数归零、删除入口 aria-label、禁用读取 watchdog；源码均按
  hash 恢复，最终 verify 在恢复后的树上通过。
- 隔离 DSH home/profile 的真实 Chrome 验收保存了 dark/light、宽栏、300px 窄栏、blocked 零/非零、
  active high/low、header 图标和 lead 选中/未选中截图。computed style 证明 active high/low 四边
  颜色与底色一致，未选中 lead 无 row ring/shadow，外部 r8→r9 后 KPI/banner/group 同步更新。
  hung-Remote 的精确恢复由 fake-timer 组件测试证明，未声称在真实窗口中注入过 hung Remote。

## 发布边界

推送 `v0.4.2-rc.8` annotated tag 后，CI 只把 6 个包 stage 到 npm dist-tag `next`。维护者必须核对本次
run 的 6 条 staged 记录并人工 approve；本候选的发布准备**不包含 approve、npm 正式发布或 GitHub
Release**。既有 tag 不移动、不删除、不重建，稳定版 `latest` 保持 `0.4.1`，直到用户明确指示稳定版。

## English

rc.8 clarifies the board entry, KPI hierarchy, status-driven four-side card borders, and a separate lead corner
badge that cannot be confused with Session selection. It also bounds every automatic board/note read with a
10-second watchdog so a never-settling Remote cannot permanently wedge watch/polling and leave blocked KPIs on
an old snapshot. Host tools, disk schemas, and DSH `0.2.2-rc.1`–`0.2.2-rc.5` compatibility are unchanged.
Verification covers unit/rendering tests, killed mutations, all three real DSH rc.5 E2E flows, package checks,
a six-package `next` dry run, and real-Chrome screenshots. Stage still requires manual approval of exactly the
six new rc.8 records; no stable release or GitHub Release is prepared here.
