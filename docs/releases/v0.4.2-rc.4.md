# v0.4.2-rc.4 — 紧凑看板 + 每项目 Markdown notes（prerelease，dist-tag `next`）

这是计划中 **0.4.2 稳定版**的第四个 prerelease 候选，取代 `0.4.2-rc.3`。本候选在保留看板自动刷新、
lead-only 与只读边界的前提下，重做更紧凑、更有视觉层级的项目卡片，并为每个项目增加可持久保存长篇
Markdown 的 notes。**board.json schema v1、既有 board 工具语义、DSH 兼容面与 `engines.dsh` 均不变**；
notes 是独立的 additive 能力。

安装时使用精确版本（发布后 24 小时内尤其不要用 `@next`，避免 pnpm `minimumReleaseAge` 回退到 npm
占位版本；详见 [PUBLISHING](../PUBLISHING.md)）：

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.2-rc.4
```

> 一旦推送，**不移动、不删除、不重建**。

## 深度 UI 打磨

- 移除卡片中「目标 / 当前焦点 / 下一步 / 任务进度 / 更新于」等逐行可见文字 label，用位置、图标、排版层级、
  原生 `title` / Tooltip 与 aria 保留完整语义；长文本仍可 hover 或展开阅读。
- 顶部状态压缩为单行 KPI pill strip，revision、更新时间与 Live 健康状态保持可见。卡片以优先级色条、
  状态点与细进度线建立视觉锚点，focus 是主文本，next 以 inline 箭头呈现。
- blocked 继续置顶并保留强警示；active 按 priority、更新时间与稳定 id 排序。右栏按实际 container 宽度
  使用 3 / 2 / 1 列，paused、done 与未列出项目保持次级折叠。
- 统一紧凑 spacing、radius 与 typography scale，减少装饰性渐变，保留 light/dark、键盘焦点、原生
  disclosure、live region 与 reduced-motion。展开任务会同时解除 focus/next/goal/blocker/task 的全部
  截断，长文本不依赖 hover 才能读全；notes 打开后聚焦返回按钮，关闭后恢复原 chip。看板仍然只读，
  自动刷新语义不退化。

## 每项目 Markdown notes

- 正文与 `board.json` 完全解耦：默认位于 `<active lead workspace>/.dsh/devlead/notes/`；显式 `boardPath`
  部署位于 `dirname(boardPath)/notes/`。每项目一个 Host 生成的安全目录，正文为 `<note-id>.md`。
- `notes/index.json` 使用 strict schema v1，保存 revision/updatedAt 与项目 note 元数据
  （id/title/summary/updatedAt/bytes/相对 path），**不保存正文**。索引最大 128 KiB，单 note 最大
  256 KiB，每项目最多 100 notes；重复 id、非法路径与路径穿越均拒绝。
- Host 使用跨进程文件锁与原子替换；只有当前 active lead AI 可写。`expected_revision` 对索引做 CAS，
  `expected_bytes` 对既有 note 做 CAS。索引是已提交事实源，崩溃后未入索引的 orphan 文件不展示。
- 新工具 `devlead_board_note_read` 按 project id/title/workspace path 与可选 note id 读取列表或全文；
  `devlead_board_note_write` 支持 create / update / append / delete。两个工具都没有路径参数，沿用
  lead-only `when` gating 与稳定 `BOARD_*` 错误码。主工具总数由 16 增至 **18**，另有 1 个 watched-child
  report 工具。
- lead 的动态 board 摘要会为 active 项目附上 note 数与最近 note 标题；整个 board + notes 摘要仍限制在
  **1536 UTF-8 bytes**，需要全文时由 lead 使用读取工具。
- 项目卡显示紧凑 notes chip（数量与最近标题）。点击后进入看板内的全栏阅读器：项目 notes 列表、长文滚动、
  标题/列表/代码块/引用/加粗等常用 Markdown 子集。所有内容都渲染为 React 元素，原始 HTML 与 XSS 字符串
  只作为文本，**不使用 `dangerouslySetInnerHTML`**，只有显式 HTTP(S) 链接可成为 anchor。
- 浏览器不新增 RPC：继续通过 `workspaceFiles.stat/readBytes/changes` 读取索引与当前 note。索引和打开的
  正文均支持 watch + 可见/聚焦页面轮询；空态、加载、坏索引、缺失/超限/坏 UTF-8 note 都局部降级，不让
  项目看板失效。

## 升级说明

- 从 rc.3 升级不需要看板数据迁移或 `/devlead reset`；board schema v1、路径、revision/CAS、权限与自动刷新
  语义不变。没有 notes index 时显示零 notes，首次写入由 Host 创建。

## 发布方式：stage → 人工 approve → GitHub Release

1. 人类明确批准后，推送指向最终 release commit 的 annotated tag `v0.4.2-rc.4`。CI 使用 OIDC trusted
   publishing，以 npm **`next`** dist-tag **stage** 全部 6 个包并生成 provenance；**stage 不公开任何内容**。
2. 维护者在 npmjs.com 网页核对本次 CI 的 6 条 staged 记录：版本必须全部为 `0.4.2-rc.4`、dist-tag 必须
   为 `next`，然后人工批量 approve。approve 即公开且不可撤销；approve 后 `next` 指向本候选，`latest`
   仍为 **0.4.1**。不要把 rc.1/rc.2 的历史记录混入本次批准；rc.1 的未 approve staged 记录仍不得 approve。
3. approve 完成并核对 dist-tags 后，使用既有 tag 和本文件手动创建 prerelease GitHub Release：

   ```sh
   gh release create v0.4.2-rc.4 --repo yankeguo/dsh-devlead --title v0.4.2-rc.4 \
     --notes-file docs/releases/v0.4.2-rc.4.md --verify-tag --prerelease --latest=false
   ```

4. 最后做三方核对：6 个包的 `@0.4.2-rc.4` 在 npm 可见、`dist-tags.next = 0.4.2-rc.4`、
   `dist-tags.latest = 0.4.1`；GitHub Release 指向 tag `v0.4.2-rc.4` 与同一 commit，
   `isPrerelease=true`、`isLatest=false`、`isDraft=false`。

## English summary

v0.4.2-rc.4 supersedes rc.3 with a denser, more visual read-only board and per-project long-form Markdown notes.
Visible field labels give way to hierarchy, icons, tooltips and accessible names; KPI pills, priority rails, status
dots and thin progress bars keep the same information in less space. Blocked projects remain prominent, active cards
sort by priority/recency, and the actual sidebar container selects three, two, or one columns. Notes live beside
board.json under `notes/`, with a strict bounded metadata index and separately capped Markdown files. The active lead
gets two additive tools for listing/reading and create/update/append/delete with index-revision and note-byte CAS;
its bounded dynamic summary includes note counts and recent titles. The client exposes compact note chips and an
immersive safe-React Markdown reader, automatically refreshing the index and open note through the existing Workspace
Files Remote without HTML injection or a new RPC. Board schema/API and the DSH rc.1–rc.5 compatibility surface are
unchanged. Nothing becomes public at stage: a maintainer must approve the six `next`-tagged rc.4 records on npmjs.com
before creating the prerelease GitHub Release, while `latest` stays 0.4.1.
