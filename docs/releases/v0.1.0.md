# v0.1.0 — dsh-devlead 首个发布

把 DeepSeek Harness 里的**一个普通会话**升级成 **DevLead 会话**：它可以直接注册
Workspace、创建和续写**普通 Session**、读取会话状态，并在被监督会话的轮次结束时被唤醒，
从而在一个人类可见、可参与的标准界面里统管多个仓库。

## 亮点

- **DevLead 模式**：每个会话一个持久开关，打开后额外获得 8 个 `devlead_*` 工具、一段
  DevLead 系统提示和状态条 UI；开关是**人类专属操作**（`/devlead on|off` 或状态条开关），
  模型没有任何工具可以自行打开。
- **产出物是标准 DSH 实体**：Workspace 真实注册进 `ctx.workspaceRegistry`，子会话是真实
  普通 Session（出现在侧边栏、可被人类打开、继续对话、归档），**不是 subagent**。
- **监督与唤醒回路**：被 watch 的会话每个 `turn/end`（完成 / 失败 / 阻塞 / 取消等）都会写入
  DevLead 会话的持久通知记录；DevLead Agent 存活时经合并窗口以一条 `devlead` 来源的消息
  唤醒它，决定下一步（继续追问、派发新任务、向人类汇报）。
- **事件溯源**：模式、watch 集合、通知全部以可忽略的 `plugin:devlead/*` Session 插件记录
  持久化（`mode` / `watch` / `notification`），严格回放校验，可跨重启 / 恢复 / fork；
  通知在 projection 内保留最近 64 条。
- **Session projection**：`devLead` projection 把模式、watch 集合、通知摘要同步到浏览器，
  UI 无需自定义 Remote API（第三方插件无法走 Typert 生成管线）。
- **8 个模型工具**：`devlead_list_workspaces` / `devlead_use_workspace` /
  `devlead_list_sessions` / `devlead_create_session` / `devlead_get_session` /
  `devlead_prompt_session` / `devlead_watch_session` / `devlead_notifications`，
  全部 `when` 门控：普通会话里不可见。
- **人类命令**：`/devlead`（状态）、`/devlead on|off`、`/devlead watch|unwatch <session>`；
  会话支持完整 id 或唯一前缀，歧义时列出候选；所有领域错误渲染成友好文本而不是抛异常。
- **状态条 UI**：composer 上方的 DevLeadBar，显示开关、监督会话数与运行中数、最近一条通知；
  开关只发送 `/devlead on|off` 命令，不引入自定义 Remote API。
- **一键安装 bundle**：`@yankeguo/dsh-devlead-bundle` 的 `cordis.patch.yml` 插入全部 4 个
  运行时插件行。

## 兼容性

- DeepSeek Harness：`>=0.2.2-rc.1 <0.3.0`（`engines.dsh`）
- Node.js：`>=24.9`（构建与发布工具链）
- 浏览器 UI：DSH 桌面端或 `dsh web`；状态条只在 Web 端渲染

## 安装

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.1.0
```

或在 Web 的 **Plugins → Add plugin** 中输入 `@yankeguo/dsh-devlead-bundle`。
安装后在 Plugins 页面确认 bundle 已启用，刷新 Web 页面。

本地 checkout 开发模式：

```sh
pnpm install && pnpm build
pnpm install:profile
```

- CI（[`.github/workflows/publish.yml`](../../.github/workflows/publish.yml)）在发布前先跑
  `pnpm install --frozen-lockfile` → `pnpm typecheck` → `pnpm test` → `pnpm build`，
  任何一步失败都不会发布；tag 门禁还会校验 `v*` tag 与全部 6 个包和根 `package.json`

  损坏记录 / 截断）、通知泵（合并窗口 / followup 内容 / dispose）、Workspace 与 Session
  编排（fake 服务）；tool 的 `when` 门控 / 参数校验 / 错误翻译 / 每个工具的 execute 转发；
  command 的语法解析 / 会话前缀寻址（唯一 / 歧义 / 缺失）/ 渲染 / 全部错误路径；
  client-ui 的纯函数（格式化 / 命令结果提取 / 样式注入契约）。

  被唤醒 → 状态条显示监督列表与通知；人类可打开子会话继续参与。

## 已知限制

- **每个 Session 一个持久模式**：打开后 DSH 重启 / 会话恢复仍然打开，需要人类 `/devlead off`。
- **冷 DevLead 会话默认不自动 resume**（`wakeColdSession: false`）：Agent 不存活时通知只留
  持久记录；需要时可配置为 true。
- **通知保留 64 条**：projection 内按常量截断，更早的记录仍在 Session 日志里。
- **监督上限默认 64、列表默认 200**：`maxWatchedSessions` / `maxListedSessions` 可调；
  命令寻址优先使用列表结果与 watch 集合，列表外的会话会回退到 core 的 `getSession` 解析。
- **不做 git 仓库创建 / clone / worktree 管理**：用 shell 工具完成，然后注册 Workspace。
- **不跨进程 / 跨 DSH 实例编排**；不新增 Remote API；不替人类做权限决策。
- **子会话是普通会话**：会出现在侧边栏并正常消耗模型额度，不是隐藏 subagent。
