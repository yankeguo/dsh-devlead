## 工具面：索引与正文分离

`devlead_board_note_write` 现在只接受：

| operation | 行为 |
| --- | --- |
| `create` | 创建索引与 note；`title` 必填、`summary` 可选，`content` 仅作可选初始正文（默认空），可生成 UUID |
| `update-metadata` | 只修改提供的 `title` / `summary`；保留正文 live mtime，无变化时不 bump revision |
| `delete` | 先提交移除 metadata 的 index，再 best-effort 删除正文；可清理缺失或非法正文的 stale entry |

旧的 `update` / `append` 与 `expected_bytes` 已移除，不再存在第二条工具正文写入路径或正文 CAS。
`expected_revision` 仍保护 index 元数据写入。create/read/list/update-metadata/delete 的返回 metadata 同时包含
root-relative `path` 与 Host 派生的 **`absolutePath`**；绝对路径只出现在结果中，不进入 strict index schema。
后续正文必须用 DSH 原生 `read` / `write` / `edit` 修改该路径，**不要手改 `notes/index.json`**，并保持合法
UTF-8、单文件不超过 256 KiB。

`devlead_board_note_read` 仍提供项目 metadata 列表和单 note 全文读取；单 note 模型结果按完整 JSON 限制为
64 KiB，超出时以 Unicode 边界截断并标记 `truncated:true`。需要修改正文时使用结果中的 `absolutePath`，
不要把截断内容当全文写回。

## Host 惰性对账与错误语义

原生编辑不经过 notes 工具，因此 index 中的 `bytes` / `updatedAt` 可能暂时落后。Host 在单 note read 或项目
list 时：

1. 与 index 写入共用 Host promise 链，并进入 index 文件的跨进程 writer lock；
2. fresh read index，逐条取得稳定正文快照，fatal-decode UTF-8 并检查 256 KiB 上限；
3. 仅在选中范围有变化时，一次性 strict-validate 并原子提交 `bytes` 与文件 mtime `updatedAt` 修复，index
   revision 加一；并发 read/list 串行后不会重复提交同一修复；
4. **从不重写正文**，不会用旧 cache 或旧正文覆盖外部/原生修改。

文件缺失返回 `BOARD_NOTE_NOT_FOUND`，非法 UTF-8 返回 `BOARD_INVALID`，超限返回
`BOARD_LIMIT_EXCEEDED`；任一选中文件失败时整个 read/list 失败，旧 index bytes 保持不变。index 修复本身
失败也不回滚原生正文。摘要仍按 cache-safe 规则降级，并在下一次成功 read/list 对账后反映新 revision。

## Client 与 prompt

- reader 仍直接通过既有 Workspace Files `stat` / `readBytes` / `changes` 读取正文，index 与当前 note 都由
  watch + visibility/focus-gated polling 自动刷新； stale index bytes 不再作为正文 watch 代际 key。
- 当前 ready 且路径匹配的 reader 标题栏优先显示成功 `stat` 的 live **观察时间**，并提供对应 live bytes。
  DSH `WorkspaceFileStat.version` 是 opaque freshness token，client **不解析它为 mtime**；`observedAt` 是
  client 观察时间，不是文件系统 mtime。note list 排序/时间与项目 chip 最新标题仍只使用 index metadata。
- 缺文件、坏 UTF-8、超限仍局部降级；旧 index 值不会导致 reader 崩溃、停止刷新或借用另一 note 的时间。
- `DEVLEAD_POLICY_BASE`、独立 `DEVLEAD_BOARD_POLICY`、两个 notes 工具 description 与 tool README 全部同步新
  职责分离；board workflow 保留主动维护看板、读取 notes、简短记录与一次性降级报告。prompt 尺寸测试继续
  限制 base ≤11,900 chars、board section 400–800 chars，本轮实测分别为 **11,899 / 799**。

## English summary

v0.4.2-rc.7 builds on the published rc.6 candidate and separates notes indexing from Markdown bodies. The write tool
now supports only create (with optional initial content), update-metadata, and delete with index-revision CAS;
update/append/expected_bytes are gone. Read/list/create results derive an `absolutePath` for DSH-native read/write/edit
without persisting it in the strict index. Serialized, locked Host reads lazily reconcile stable file bytes and mtimes,
never rewrite native edits, and fail closed without damaging the old index on missing, oversized, or invalid-UTF-8
bodies. The read-only client follows native edits through watch/poll and shows the selected document's successful-stat
observation time without parsing DSH's opaque version token. All prompt sections and tool descriptions preserve rc.6's
proactive board workflow under the same size budgets. Verification passes 53 files/1850 tests, two killed-and-restored
mutations, all three real DSH rc.5 e2e flows, package checks, and the six-package `next` dry run. Stage publishes
nothing: maintainers must approve only the six new rc.7 records before creating the prerelease GitHub Release;
`latest` stays 0.4.1.
