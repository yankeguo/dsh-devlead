# v0.4.2-rc.9 — 侧栏内联角标与可访问性补强（prerelease，dist-tag `next`）

`0.4.2-rc.9` 是计划中的 `0.4.2` 补丁版候选，基于已 staged 但未 approve 的 `0.4.2-rc.8`。
本候选只改变 client-ui、测试、文档与版本号，不改 Host 数据层、工具、board/notes schema、Remote、
`dsh.client.inject` 或 DSH 兼容面；**不是稳定版**。

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.2-rc.9
```

## 相对 rc.8 的变化

- **P1 — 侧栏 lead 角标不再覆盖 shell 内容**：active lead 的 sparkle + `LEAD` 角标从绝对定位改为
  `sidebar.session.row.trailing` 的内联 flex 布局，位于 time 之后，并与独立 action strip 分工。
  触屏或窄栏下 time、badge、actions 不再相互重叠。shell 行的 border、background、padding、height、
  position 以及选中/hover/focus 样式仍不由插件修改；watched 行的弱化准星保持不变。
- **P3 — trailing 隐藏时仍有 lead 可访问文本**：`sidebar.session.row.leading` 新增仅 active lead
  渲染的 visually-hidden lead 说明。shell 在 hover、键盘 focus 或菜单打开时以 `display:none` 隐藏
  trailing seat，此时可访问树仍保留 lead 身份，而不增加第二个可见标记。既有
  `sidebar.session.row.hover` 说明继续保留，active lead 与 watched 角色都仍可在 hover card 中阅读。
- **P3 限制如实保留**：Session active 时，shell 的高优先级状态点会替换 leading seat；此状态下常驻
  visually-hidden lead 文本不可用，hover card 是补充说明，不能据此声称仍有同等的常驻 leading AX 文本。
  blank 行与搜索结果行的既有 shell seat 限制也不因本候选消失。
- **P4 — 回归测试补强**：新增或加强共享只读文件状态机的 watchdog error/read 断言与 hung `readBytes`
  恢复覆盖，并补充全 0 KPI 和 guide icon 测试。这些是用例范围说明，不在此预写最终通过数量。
- **P2 — 文档与版本准备**：README 中英文、发布流程、架构兼容性说明与本 release notes 同步到 rc.9；
  根 manifest 与 6 个可发布包统一为 `0.4.2-rc.9`。rc.8 的看板入口/KPI/卡片层级、共享状态汇总和
  Workspace Files 读取 watchdog 保留，rc.7 的原生 notes 编辑与主动 board workflow 也保留。

## 发布边界

推送 `v0.4.2-rc.9` annotated tag 后，CI 只把 6 个包 stage 到 npm dist-tag `next`。维护者只能批准
**本次 CI 为 rc.9 生成的 6 条 staged 记录（`next`）**；rc.8 已 staged 未 approve，其记录不得混入，
历史 rc.1/rc.4 的未批准 staged 记录同样不得批准。本候选的发布准备不包含 approve、npm 正式发布或
GitHub Release。既有 tag 不移动、不删除、不重建，稳定版 `latest` 保持 `0.4.1`，直到用户明确指示稳定版。

## English

rc.9 builds on the staged but never-approved rc.8 candidate. The active lead badge now uses the trailing seat's
inline layout instead of absolute positioning, preventing time/badge/actions overlap on touch devices and narrow
sidebars without changing shell row or selection styles. A visually hidden lead description in
`sidebar.session.row.leading` preserves the lead fact for assistive technology when hover, keyboard focus, or an open
menu hides the trailing seat; the existing hover card remains. When a higher-priority status dot replaces the leading
seat, that persistent text is unavailable and the hover card is only a supplement—this shell limitation is not
claimed to be fully solved.

Regression coverage now includes watchdog error/read assertions, recovery from a hung `readBytes`, all-zero KPIs,
and the guide icon. Documentation and all seven workspace manifests are prepared for rc.9. Host tools, disk schemas,
Remote, client injection, and DSH `0.2.2-rc.1`–`0.2.2-rc.5` compatibility are unchanged. Verification passed 53 files /
1863 tests, package checks, the six-package `next` dry run, and all three real DSH rc.5 E2E flows (244/244, 244/244,
and 220/220). New real-Chromium screenshots cover selection, theme, the 264px sidebar, hover, and keyboard focus;
touch emulation was not completed and is explicitly excluded from the visual PASS claim. See the release evidence for
logs and boundaries. Approval is limited to exactly the six new rc.9 staged records on `next`; rc.8 and the historical
rc.1/rc.4 staged records must not be mixed in.
