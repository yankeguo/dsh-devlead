# v0.2.5 — 全局单活、被监督会话汇报与可靠投递

0.2.5 是 **patch 版本**，不包含 breaking change：人类命令、已有 13 个主工具、watch / 归档 /
preset 选择等产品语义、`engines.dsh`（仍为 `>=0.2.2-rc.1 <0.3.0`）都不变。本版加入全局
单活约束、被监督会话的中途汇报工具、报告 durable outbox，并修复 archived 占用者永久阻塞
准入的问题。

## 全局最多一个 DevLead-enabled Session

- DevLead 模式现在是 **Host 级单活资源**：无论跨多少 Workspace，同一时刻最多一个 Session
  可以 enabled。
- 第二个 Session 执行 `/devlead on` 会以稳定错误码 **`DEVLEAD_ALREADY_ACTIVE`** 被拒绝；
  错误消息给出占用者的 `title (session-id)`（无 title 时为裸 id），并提示先在占用者执行
  `/devlead off`。被拒绝方 projection 保持 disabled，UI 开关保持 off，失败走既有 composer
  失败通道。
- 准入在 Host service 的串行临界区内完成，扫描 live projection + durable corpus（projection
  cache active 行精确 fold、inactive 行零 I/O、unknown 行有界读取）。
- `off` / `reset` 立即释放。归档 holder 不再阻塞准入；DevLead 仍 best-effort 写
  durable mode-off，写不掉时记录 durable tombstone、warning，并继续准入。
- 启动 / rehydration 合并 live 与 cold active，按确定性排序保留一个并对其余写 mode-off；
  archived holder 只尝试释放、不参与 keeper/blocker 排序。被 unarchive/打开的 holder 会在
  `agent/created` reconciliation 时写 mode-off 并清除 tombstone，不会双活。
- `/devlead status` 新增 `Archived DevLead holders (ignored for admission)` 区块，列出仍
  enabled 的 archived Session，并提示 unarchive 后执行 `/devlead off`，或删除。

## 被监督 Session 中途汇报：`devlead_report`

- 新增第 14 个工具 `devlead_report`，只在「非 DevLead + 被唯一 active lead watch」的 Session
  可见/可执行；没有 target 参数，不能向任意 Session 乱发。
- 参数：`message`（必填，≤4000 码点）、`kind?`（`progress` / `blocked` / `decision` /
  `fyi`，默认 progress）、`summary?`（≤200 码点）。
- 单向汇报，不是提问/等待回复通道；子 Session 调用后立即返回，最终完成仍走原 turn 结束
  通知。lead 之后可用 `devlead_prompt_session` 正常 steering。
- 同轮相同消息幂等；每轮最多 4 条不同报告，超出返回
  `DEVLEAD_REPORT_RATE_LIMITED`；空/超长/非法 kind 返回 `DEVLEAD_INVALID_INPUT`；关系不成立
  返回 `DEVLEAD_NOT_SUPERVISED`。
- 新增 `devlead:report-policy` system prompt（只对被监督普通 Session 注入），lead policy 也
  增加收到 `[DEV LEAD REPORT]` 后的处理口径。
- 报告写入 lead 的 durable `plugin:devlead/report` 记录，fold 为 `devLead` projection 新增的
  `reports` 数组（`stateVersion` 2，旧 cache 行会失效并 refold）。lead 的 DevLeadBar、
  `/devlead` status、`devlead_notifications` 以及读取 lead 自身的 `devlead_get_session` 均可
  看到 kind / sender / summary；UI 按 `at` 合并最新通知与报告。

## 报告 durable outbox（不静默丢失）

- `devlead_report` 成功前先把 receipt 写入 Host `ctx.storageDomain` 的 durable outbox
  （domain `devlead_report_outbox`，per-record 原子写，写 resolve 即 durable）。
- 随后才尝试把 receipt 追加到 lead Session log，并且 **`ctx.sessions.flush` 成功后**才删除
  outbox 行。cold / archived / 未 attached / watch 暂时消失时行保留，在 service init、
  storage 晚挂载、`agent/created`、`setEnabled(true)`、`watchSession(true)` 时 replay。
- 回执新增 `durable` / `queued` / `warning?`：Host 未组合 `storageDomain` 或被显式禁用时，
  返回 `durable:false` + warning，明确说明仅内存、Host 退出可能丢失，不再静默声称已持久化。
- outbox 行按 7 天 retention 清理；`/devlead reset` 丢弃该 lead 的待投递行；lead 被删除且
  不返回到期后清理。
- 默认 Web 组合的 e2e 已实测 `storageDomain` 存在，报告回执为
  `durable:true, queued:false`。

## 客户端 UI

- composer 工具条的 DevLead 开关在 enabled 时使用 business-accent 边框与浅色 halo；off 态
  保留透明边框，因此不会产生布局位移。pending / failure / pressed / hover / focus 与既有
  tooltip/live region 行为保持。
- DevLeadBar 合并最新通知与最新 report：显示 sender、本地化 kind、summary/消息摘要，tooltip
  使用 Host canonical `reportLine`；状态条仍只读、不带开关。

## 已知限制

- Host 未组合 `storageDomain` 时报告回执为 `durable:false`（显式警告）；此时 cold/未 attached
  lead 的行只在进程内，Host 退出可能丢失。
- outbox 行最多保留 7 天；损坏的 outbox 派生记录按 `backup-and-skip` 跳过并 warning。
- 未归档且 cold、无法 resume 的 DevLead holder 仍会阻塞准入（真实 enabled lead，需打开或
  删除）；archived holder 才是无需运行 Session 即可解除的路径。
- outbox 清理/准入 mutex 仍是单 Host 进程语义；跨进程共享同一持久存储没有跨进程锁。
- 正向 model pin E2E 依赖 Host provider 凭据；本机缺失时如实 SKIP，负向与目录路径仍测试。
- worktree 隔离仍只保证 rc.4 的完整 E2E；rc.1–rc.3 只跑 `--no-worktree` 矩阵。
