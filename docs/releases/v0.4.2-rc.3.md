# v0.4.2-rc.3 — Client 看板自动刷新 + 全面视觉重做（prerelease，dist-tag `next`）

这是计划中 **0.4.2 稳定版**的第三个 prerelease 候选，取代 `0.4.2-rc.2`。相对 rc.2，本候选的变化
集中在 **client 看板**：所有文件状态都有自动刷新，页面隐藏/失焦时暂停，重做状态概览、分组与卡片视觉。
**Host 看板 schema v1、Host API、模型工具、错误码、projection 契约与 DSH 兼容面均不变**；rc.1/rc.2 的
历史 release notes 保持原样。

## 相对 rc.2：自动刷新

- **保留文件 watch**：继续消费 `workspaceFiles.changes`，change 经 **120ms debounce** 后重读；旧 request
  generation 不得覆盖新路径/新读取结果。
- **所有状态都有周期轮询**：ready/loading 默认按固定 **5s** 节奏读取；empty/error 从 **5s** 起指数退避，
  依次为 5s → 10s → 20s → 30s，之后保持 **30s** 上限。不再只有 empty 才轮询，读取/解析错误与健康
  看板都能自动跟进后续变化。
- **只在页面活跃时轮询**：document 必须同时 visible 且 focused。blur/hidden 后暂停并清理 timer；
  visibilitychange/focus 恢复时立即触发一次 coalesced read。unmount 与 path change 同样清理旧 timer，
  不得继续读取旧路径。
- **共享 in-flight 去重 + trailing refresh**：watch、poll、focus/visibility 恢复共用同一个在途读取；
  在途期间新到的 watch ready/change 合并为一次 trailing refresh（poll/focus 只共享当前读取），既不叠发，也不让后续 change 等到下一轮 poll。
  手动刷新仍可强制取代在途读取、重读文件并重建 watch。
- **watch ended 不等于停止更新**：change stream 结束后不静默自动重连，但周期轮询继续；Live 文案分别
  表达文件监听与自动轮询状态。手动刷新仍是强制重读/重连入口，而不是后续内容更新的唯一途径。

## 相对 rc.2：视觉与交互

- 顶部新增 **active / blocked / paused / done KPI**，并集中展示 revision、updated 相对时间与 Live 自动
  刷新 active/paused/disabled 状态。
- **blocked 强警示并置顶**；active 是主内容区，宽右栏响应式 **2 列**、窄栏 **1 列**。同组仍按
  priority、updatedAt 与 id 稳定排序。
- 卡片突出 focus/next/blocker，新增任务 done/total 进度与进度条，任务详情继续使用原生 disclosure。
- paused/done 与未在看板中的 workspace 使用次级折叠，降低已收尾内容对主工作区的干扰。
- loading/empty/error、长文本、light/dark、标题关联、状态 live region、任务进度 aria、键盘 disclosure
  与焦点可见性均纳入验收；面板仍然只读，只有刷新/重试与展开控件，没有看板写能力。

## 升级说明

- 从 rc.2 升级不需要看板数据迁移或 `/devlead reset`；board schema v1、文件路径、revision/CAS、Host 写入
  与权限语义不变。
- 从 0.4.1 升级仍无需迁移或重置；看板默认启用及 `boardPath` override 语义与 rc.2 相同。
- 从低于 0.4.0 的版本升级时，0.4.0 的 breaking 升级注意事项仍然适用，详见
  [v0.4.0 release notes](v0.4.0.md) 与 [COMPATIBILITY](../COMPATIBILITY.md)。
- 页面 hidden/blur 时自动轮询暂停是预期行为；恢复 visible + focused 会立即读取。watch ended 时若页面
  活跃，轮询仍继续；需要强制重读或重连时可手动刷新。

1. 人类明确批准后，推送指向最终 release commit 的 annotated tag `v0.4.2-rc.3`。CI 使用 OIDC trusted
   publishing，以 npm **`next`** dist-tag **stage** 全部 6 个包并生成 provenance；**stage 不公开任何内容**。

   为 `next`，然后人工批量 approve。approve 即公开且不可撤销；approve 后 `next` 指向本候选，`latest`

3. approve 完成并核对 dist-tags 后，使用既有 tag 和本文件手动创建 prerelease GitHub Release：

   ```sh

     --notes-file docs/releases/v0.4.2-rc.3.md --verify-tag --prerelease --latest=false
   ```

4. 最后做三方核对：6 个包的 `@0.4.2-rc.3` 在 npm 可见、`dist-tags.next = 0.4.2-rc.3`、

   `isPrerelease=true`、`isLatest=false`、`isDraft=false`。

## English summary

v0.4.2-rc.3 supersedes rc.2 with client-board changes only. It keeps the 120 ms file-change debounce and adds
polling in every state: a fixed 5 s cadence for ready/loading, and 5 s exponential backoff capped at 30 s for
empty/error. Polling runs only while the document is visible and focused; resume triggers an immediate coalesced
read, timers are cleaned up on blur/hidden/unmount/path changes, and watch/poll/resume triggers share one
in-flight read plus at most one trailing refresh, so later changes are neither duplicated nor dropped. An ended
watch does not reconnect silently, but polling continues; manual refresh still forces a
read and reconnects. The redesigned read-only UI adds status KPIs, revision/updated/Live health, a prominent
blocked area, responsive active cards with focus/next/blockers and task progress, and secondary paused/done/
unlisted disclosures, with light/dark, aria and keyboard acceptance coverage. The Host board schema/API and DSH
compatibility surface are unchanged. The final frozen tree passed 1,756 unit/render tests, package checks,
6-package dry-run preflight, and all three rc.5 E2E flows (238/238 patch, 238/238 installed, 214/214 without
worktree). Mutation checks fail when polling or blocked-first ordering is removed. Isolated-browser evidence
covers wide/narrow responsive layouts, light/dark tokens, automatic r42→r43 updates, blur/focus status, and
keyboard disclosures. Nothing becomes public at stage: a maintainer must approve the six
`next`-tagged rc.3 records on npmjs.com before creating the prerelease GitHub Release, while `latest` stays 0.4.1.
