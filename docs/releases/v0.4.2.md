# v0.4.2 — 项目看板、项目笔记与自动刷新进入稳定版

0.4.2 是 **0.4.1 的补丁版**：没有公网 API 破坏性变更——既有工具的名称、参数、错误码词表、projection
契约与持久记录都保持不变，新增的工具与字段均为 additive；`engines.dsh` 仍为 `>=0.2.2-rc.1 <0.3.0`，
DSH 兼容面仍为 `0.2.2-rc.1` – `0.2.2-rc.5`。它把 0.4.1 之后的项目看板、项目 Markdown notes、自动
刷新/watch、紧凑响应式 UI、prompt 引导与 blocked KPI 修复全部带入稳定通道；发布目标 dist-tag 为
**`latest`**（stage 后由维护者在 npmjs.com 人工 approve 才公开）。

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.2
```

## 自 0.4.1 以来的内容

### 项目看板：默认启用、跟随 active lead

- **零配置默认开启**：唯一的 active lead 自动获得项目看板，文件派生自该 Session 创建时的原始 workspace
  根 `<workspace>/.dsh/devlead/board.json`；worktree 隔离的 lead 也把看板放在项目根。同一时刻最多一个
  store 与一个目录 watcher，`/devlead off`、lead 切换或 workspace 根变化时先释放旧 store/watcher 再切换，
  读取不会看到半切换状态。
- **没有可用 lead / workspace 根时安全禁用**：没有 lead、没有绝对 workspace 根、或派生 workspace 根已不
  存在时，看板以 `BOARD_DISABLED` 禁用（`boardDisabledReason` 分别为 `no-workspace` /
  `missing-workspace` 等）；Host **不会重建**缺失的 workspace，也不会迁移旧看板文件。
- **start 失败只降级**：父目录预创建 / `start()` 失败只记录 warning 与 `boardStartError`，DevLead 服务、
  工具、命令与 UI 照常加载；工具按真实故障返回 `BOARD_IO_ERROR`，同一路径的下一次 lead 同步会按需重试。
- **显式 `boardPath` 部署语义不变**：仍必须是绝对路径、优先于 workspace 派生、`start()` 时以 `0700` 幂等
  预创建父目录（不改已有目录权限）；写入仍是同目录临时文件原子替换 + 跨进程文件锁，文件权限 `0600`。
- **工具边界**：`devlead_board_read` 结果上限 64 KiB，超限时按 tasks → blockers → whole project 的顺序从
  尾部整行裁剪并标 `truncated:true`，不返回 schema-invalid 片段；`devlead_board_update` 的 project 引用在
  锁内 fresh snapshot 上解析，长 workspace path/title 不再误报 `BOARD_LIMIT_EXCEEDED`。
- 看板 schema v1、分组/排序、revision/CAS、错误码与磁盘契约以 [BOARD](../BOARD.md) 为准。

### 项目 Markdown notes：索引 + 原生编辑

- 每个项目可以有一组 Markdown notes，与看板同生命周期、同 active lead 所有权，但使用独立文件：默认位于
  `<workspace>/.dsh/devlead/notes/`（显式 `boardPath` 部署为 `dirname(boardPath)/notes/`），每项目一个
  Host 生成的安全目录，正文为 `<note-id>.md`，`notes/index.json` 使用 strict schema v1（索引文件上限
  128 KiB）。
- 模型用 `devlead_board_note_write` 创建 / 改元数据 / 删除索引（`expected_revision` 保护 index CAS），
  用 `devlead_board_note_read` 读取项目 metadata 与单 note 全文；**正文改用 DSH 原生的 `read` / `write` /
  `edit` 编辑**工具结果里的 `absolutePath`，插件不再提供第二条写正文的路径。
- Host 在 read/list 时惰性对账 index 的 `bytes` / `updatedAt`，只修复元数据、**从不重写正文**；正文缺失、
  非法 UTF-8、超限分别返回 `BOARD_NOTE_NOT_FOUND` / `BOARD_INVALID` / `BOARD_LIMIT_EXCEEDED`，坏
  index/坏 note 只局部降级，不影响看板。
- 浏览器端按项目显示 notes chip / 数量 / 最新标题，并在右侧栏提供安全的只读 Markdown reader（无 raw-HTML
  sink）；index 与当前 note 都由 watch + 可见性轮询自动刷新，reader 标题栏显示成功 stat 的 live 观察时间。
- 单 note 工具读取上限 64 KiB（Unicode 边界截断并标 `truncated:true`）；正文文件上限 256 KiB，每项目最多
  100 条 note。写盘前拒绝大小写不敏感的重复 note id（`CaseNote` ≡ `casenote`）与 Windows 保留名
  （`CON` / `PRN` / `AUX` / `NUL` / `COM1`–`COM9` / `LPT1`–`LPT9` 变体），避免跨平台路径冲突。迁移/备份与
  手改 index 的恢复规则见 [BOARD](../BOARD.md)。

### 自动刷新与 watch

- 看板文件变化经 `workspaceFiles.changes` watch，120ms debounce 后重读；所有状态都有周期轮询：
  ready/loading 固定 5s，empty/error 从 5s 起退避到 30s 上限。
- 轮询只在页面 **visible 且 focused** 时运行；blur/hidden 暂停并清理 timer，恢复时立即触发一次合并读取；
  unmount 与路径切换清理旧 timer，旧读取不得覆盖新路径。
- watch、poll、focus/visibility 恢复共享同一个在途读取，途中新到的事件合并为一次 trailing refresh；
  watch 结束不自动重连但轮询继续，手动刷新仍强制重读/重连。
- 每次自动读取有 10 秒 watchdog：Remote `stat`/`readBytes` 永不 settle 时先完成 error 收尾再 abort 旧
  controller，后续自动触发可以开启新 generation，不会永久卡住 watch trailing 与后续轮询。

### 紧凑响应式 UI 与可读性

- 顶部 KPI 固定为 blocked → active → paused → done 单行 pill strip，带状态图标、零值中性、blocked>0 才
  强 warning；blocked 警示置顶，active 是主内容区，右栏按容器宽度适配窄栏 1 列 / 宽栏 2 列 / 更宽栏
  3 列，更窄时优雅换行/收缩而不横向溢出（极窄栏的 KPI strip 可横向滚动并支持键盘聚焦）；paused/done
  与未在看板中的 workspace 使用次级折叠。KPI、项目分组与 blocked banner 由同一份汇总派生。
- 卡片为固定的十个 section（title / workspace / meta / focus / next / goal / blockers / progress / tasks /
  footer），同一视觉行的卡片共享父网格轨道，长短内容混合时逐块对齐；非 subgrid 环境保留等高降级。
  focus/next/goal 有行数上限，空字段保留不可见占位，原生 title 与任务 disclosure 提供全文。
- priority 从重复文字 badge 改为标题行最右的高/中/低形状图标（双上 / 单上 / 下单，形状本身可区分），带
  本地化 tooltip 与 ARIA；移除卡片标题左侧旋转状态点，LIVE 与手动刷新动画保留。
- 面板 header 只保留一行：LIVE、updated 相对时间与 rN、最右刷新按钮；tab 标题不再重复。
- 侧栏 active lead 行只在右上角显示 sparkle + `LEAD` 小角标（带本地化 aria-label/title），不再画整行
  overlay ring；watched 行继续用弱化准星标记；shell 的选中、hover、focus 样式不变。

### Prompt 引导与工具描述

- 新增仅对 lead 可见的 system prompt section `devlead:board-policy`（正文 `DEVLEAD_BOARD_POLICY`）：引导
  lead 在派发、收口与跨轮恢复时主动维护项目看板和 notes；普通 Session 与 subagent 的 prompt 不包含该段。
- 四个看板/notes 工具补齐使用场景描述，模型更清楚何时读取、何时更新、何时用原生文件工具改正文；prompt
  尺寸预算与既有工具语义不变。

### 模型工具变化

- 主工具从 0.4.1 的 **14 个增至 18 个**：新增 `devlead_board_read` / `devlead_board_update` 与
  `devlead_board_note_read` / `devlead_board_note_write`；另有 1 个 watched-child 单向
  `devlead_report`。既有 14 个工具的名称、必填参数与语义不变。
- 看板/notes 工具从不接受文件路径参数；所有读写都经 Host 服务与稳定的 `BOARD_*` 错误码。
- 命令面无变化：`/devlead` 的集合与参数沿用 0.4.1，看板/notes 没有新增人类命令入口。

## 从 0.4.1 升级

- **无需迁移、无需重置**：DevLead 的 mode/watch/通知/answer 状态与持久记录完全兼容，不需要
  `/devlead reset`。
- 项目看板与 notes 是新增的默认开启功能；首次启用 lead 后会在其原始 workspace 根下创建
  `.dsh/devlead/board.json` 与 `.dsh/devlead/notes/`（父目录 `0700`、文件 `0600`）。若仓库不希望这些
  运行状态进入 Git，由用户自行加入 `.gitignore`；插件不修改 `.gitignore`。
- 显式配置 `boardPath` 的部署路径、权限与 CAS 语义不变；其 notes 根为 `dirname(boardPath)/notes/`。
- 从低于 0.4.0 的版本直接升级时，0.4.0 的 breaking 注意事项仍然适用（旧 DevLead state 不迁移，需
  `/devlead reset`），详见 [v0.4.0 release notes](v0.4.0.md) 与 [COMPATIBILITY](../COMPATIBILITY.md)。

## 兼容性

- DSH 兼容面仍是 **`0.2.2-rc.1` – `0.2.2-rc.5`**，`engines.dsh` 仍是 `>=0.2.2-rc.1 <0.3.0`；本地类型
  基线固定 rc.1，运行时在安装版 rc.5 上验证。
- 只使用既有 Host API（`webserver/index-inject`、`sidebarRight*`、Workspace Files Remote、
  `@deepseek-ai/dsh-atomic-write`、`systemPrompt.context` 等），不引入 0.2.3-only API，也不新增 Remote
  或 `dsh.client.inject` 项。
- UI 只在 **Web** 平台渲染；DevLead 面向默认 Web 组合（`dsh-base` + `dsh-web-app`）构建，不需要额外
  实验性 bundle。

## 已知限制

- **`boardPath` override + 页面早于 lead 加载**：late-enable 场景需要刷新一次页面才能拿到 override 路径与
  `override:true`；默认派生路径的 late-enable 不需要刷新。
- **看板禁用条件**：没有 active lead、没有绝对 workspace 根或派生 workspace 根缺失时看板禁用；Host 不重建
  缺失的 workspace，也不会迁移旧看板文件。
- **notes 正文编辑**：正文必须使用 DSH 原生 `read` / `write` / `edit`，不要手改 `notes/index.json`；原生
  编辑后 index 的 bytes/updatedAt 可能短暂落后，Host 会在下一次 read/list 时惰性对账。
- **浏览器视觉/主题/交互**仍需按 [UI-VERIFICATION](../UI-VERIFICATION.md) 在隔离 profile 人工验收；
  自动化覆盖到 projection/DOM/断言层，不替代人工走查。
- 搜索态结果行与 blank 行没有 trailing seat，因此不显示 active/watched 标记；这是 shell 限制，不是 bug。

## 发布方式

推送指向 release commit 的 annotated tag `v0.4.2` 后，`.github/workflows/publish.yml` 以 OIDC trusted
publishing 以 npm dist-tag **`latest`** **stage** 全部 6 个包（带 provenance）；stage 不公开任何内容。
维护者需在 npmjs.com 网页核对 6 条 staged 记录（版本 `0.4.2`、dist-tag `latest`）并人工 approve；
approve 前 `latest` 仍为 **0.4.1**，approve 后 `latest` 指向 **0.4.2**。

approve 完成后，使用本文件手动创建 GitHub Release：

```sh
gh release create v0.4.2 --repo yankeguo/dsh-devlead --title v0.4.2 \
  --notes-file docs/releases/v0.4.2.md --verify-tag --latest
```

tag `v0.4.2` 一旦推送，**不移动、不删除、不重建**。

## English summary

v0.4.2 is a patch release with no breaking public API changes: existing tool names, parameters, error codes
and projection contracts are unchanged, and every addition is additive. It promotes the 0.4.1 follow-up
work to the stable channel; the release targets npm dist-tag `latest` (prereleases use `next`), with
publication pending maintainer approval of the staged packages. The lead-only project board is now
**enabled by default** and derives `<workspace>/.dsh/devlead/board.json` from the active lead's original
workspace root; it is disabled (`BOARD_DISABLED`, `no-workspace` / `missing-workspace`) instead of inventing
a path or recreating a missing workspace, an explicit `boardPath` keeps its absolute-path, pre-create, CAS
and `0600` semantics, and a board start failure degrades only the board (`BOARD_IO_ERROR`). The tool-facing
board read is capped at 64 KiB with tail-trimmed `truncated:true` results, and long workspace path/title
project references no longer false-fail. Per-project Markdown notes use a strict metadata index plus separate
bodies: lead tools create, update metadata and delete index entries with CAS, while bodies are edited with
DSH's native `read` / `write` / `edit` via the returned `absolutePath`; the Host lazily reconciles
bytes/updatedAt without ever rewriting bodies, and the client shows note chips plus a safe read-only Markdown
reader. The board refreshes from a 120 ms-debounced file watch plus visibility/focus-gated polling (5 s ready,
5–30 s backoff for empty/error, one in-flight read with trailing refresh), an ended watch keeps polling, and a
10 s watchdog prevents a hung Remote from stalling refresh and the blocked-KPI view. The UI adds a single-line
KPI strip, prominent blocked banner, responsive 2/3/1-column status-bordered cards with ten subgrid-aligned
sections and title-row priority glyphs, a compact one-line header, and a trailing-seat sparkle/`LEAD` sidebar
badge that does not alter shell selection, hover or focus. A lead-only `devlead:board-policy` system prompt
section guides proactive board/notes maintenance. Upgrading from 0.4.1 requires no migration or
`/devlead reset`; the first lead run creates `.dsh/devlead/board.json` and `.dsh/devlead/notes/` under the
workspace root. DSH compatibility stays `0.2.2-rc.1` – `0.2.2-rc.5` with `engines.dsh >=0.2.2-rc.1 <0.3.0`;
upgrading from below 0.4.0 keeps the 0.4.0 breaking notes.
