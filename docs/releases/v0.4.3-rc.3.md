# v0.4.3-rc.3 — `boardPath` 重命名为相对状态目录 `statePath`（prerelease，dist-tag `next`）

这是计划中 **0.4.3** 版本的第三个 prerelease 候选，完整保留 rc.1/rc.2 的契约变更，并追加一项
**0.x 允许的破坏性配置变更**：DevLead 部署配置 `boardPath` 重命名为 `statePath`，值从精确 board
JSON 文件路径改为 board/notes 共用的**相对状态目录**。本候选包含功能提交 `bb3bd5b`、旧键专门迁移
提示清理 `6bdd7a4`、内部/线缆标识符重命名 `ec06b52`，以及补齐同一重命名的 `7e84167`。

本候选不改 DSH 兼容面：`0.2.2-rc.1` – `0.2.2-rc.5` 与
`engines.dsh: >=0.2.2-rc.1 <0.3.0` 均保持不变。稳定版 `latest` 仍为 **0.4.2**；stage 本身不公开
任何包，也不改变公开 dist-tag。

> 本文件是 GitHub Release 正文。文件提交与 tag/CI stage 不代表已经 approve 或创建 GitHub Release；
> 后续 approve 必须由维护者在 npmjs.com 网页人工完成。tag 一旦推送，**不移动、不删除、不重建**。

## 升级步骤

### 1. 先检查并备份部署配置与状态文件

在加载 rc.3 之前，检查 profile 的 `cordis.patch.yml` 中 loader row `devlead` 的 `config.boardPath`。
如需移动文件，先在 `/devlead off` 或停止相关 Host 后备份旧 `board.json` 及其同级 `notes/` 目录。

**不要直接带着旧 `boardPath` 升级。** rc.3 已删除旧键的专门迁移提示；未知配置键按 DSH 框架默认行为
静默忽略。因此，旧 `boardPath` 不会触发 `/boardPath` 错误，也不会继续选择旧看板：若未配置新的
`statePath`，Host 会使用默认 `.dsh/devlead`。

### 2. 把精确 board 文件配置改为状态目录配置

例如 lead 的原始 workspace 根是 `/work/project`，旧配置为：

```yaml
boardPath: custom/board.json
```

改为：

```yaml
statePath: custom
```

新的派生结果固定为：

```text
board = <workspace>/<statePath>/board.json
notes = <workspace>/<statePath>/notes/{index.json,<project>/<note-id>.md}
```

因此上例仍使用 `/work/project/custom/board.json`，notes 自动跟随到 `/work/project/custom/notes/`，
没有独立 notes 路径配置。不要再写 `statePath: custom/board.json`：它表示目录，会派生出
`custom/board.json/board.json`，并不是旧语义的别名。

未配置旧 `boardPath`、一直使用默认路径的部署无需改配置，默认仍是
`<workspace>/.dsh/devlead/board.json` 与 `<workspace>/.dsh/devlead/notes/`。注意 rc.3 中空白
`statePath` 不是默认值别名；使用默认值应省略该键。

### 3. 按需移动 workspace 外看板与 notes

如果旧看板已经位于原始 workspace 内，且旧文件名为 `board.json`，按上例改配置后无需移动文件。
旧 `dirname(boardPath)/notes/` 会自动成为新 `statePath` 下的 `notes/`。

如果旧看板位于 workspace 之外，必须先把 `board.json` 和同级 `notes/` 一并移入原始 workspace，
再配置相对目录。例如把 `/srv/devlead/board.json` 与 `/srv/devlead/notes/` 分别移到
`/work/project/custom/board.json` 与 `/work/project/custom/notes/`，然后使用 `statePath: custom`。
workspace 外看板不再受支持。旧自定义文件名不是 `board.json` 时，还需将文件改名为目标状态目录下的
`board.json`。

无需迁移 `board.json` 或 notes 的内容/schema，也无需 `/devlead reset`；迁移只涉及部署配置键及必要的
文件位置调整。

### 4. 核对路径安全约束

- `statePath` 只接受使用 `/` 分隔的相对目录；拒绝 POSIX 绝对路径、Windows 盘符路径与 UNC 路径。
- 拒绝反斜杠、空路径段与 `..` 逃逸（例如 `../x`、`a/../../x`）；解析结果必须仍在原始 workspace 根内。
- 非法 `statePath` 会在 Loader 校验或直接构造服务时以 `BOARD_INVALID` + `/statePath` validation issue
  **fail-fast**，不会静默回退到默认看板。
- 最终派生的 `board.json` 不能是 symlink；状态目录及其父目录链中的 symlink 可接受。
- 默认与自定义 `statePath` 都相对 active lead Session **创建时的原始 workspace 根**
  （`SessionHeader.cwd`），不是某次 turn 的 effective/worktree cwd。
- 原始 workspace 根必须仍存在且是目录；缺失时看板保持 disabled，Host **不会重建 workspace**。

### 5. approve 后安装精确版本并验证

维护者在 npmjs.com 网页 approve 本次 6 条 staged 记录后，使用精确版本安装；发布后 24 小时内尤其
不要用 `@next`，避免 pnpm `minimumReleaseAge` 回退到 npm 占位版本：

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.3-rc.3
```

按正常插件升级流程重新加载 DSH 后，确认看板与 notes 都能从迁移后的路径读取。rc.1 的工具参数、CAS
与模型路由 breaking 迁移要求仍然适用，详见
[v0.4.3-rc.1 release notes](v0.4.3-rc.1.md)；rc.2 的 workspace 相对位置要求也继续适用。

## Breaking：配置项与目录派生

支持的配置示例：

```yaml
- id: devlead
  name: '@yankeguo/dsh-devlead'
  config:
    # 保留部署需要的其他 devlead config 键；DSH 整体替换一行的 config。
    statePath: custom/state
```

对应 `<workspace>/custom/state/board.json`、`<workspace>/custom/state/notes/index.json` 与
`<workspace>/custom/state/notes/<project>/<note-id>.md`。省略 `statePath` 时默认 `.dsh/devlead`。
`6bdd7a4` 只删除旧 `boardPath` 的专门迁移提示，不增加替代警告；未知键按框架默认静默忽略。

## 外部契约与内部字段命名

- board/notes wire schema、文件 revision、per-project board CAS、notes index CAS、读写锁与四个 board/notes
  工具的参数/结果/权限语义均不变。
- 除部署配置键改名为 `statePath` 外，浏览器 global 中 Host 已解析的绝对 **`boardPath`** 字段改名为
  **`boardFilePath`**；Host 的内部布尔 **`boardPathOverride`** 改名为 **`statePathOverride`**，Host/client
  两端同步。跨 rc.3 前后的 Host/client 混装不保证 board global 兼容。
- 页面在 lead 启用前加载时，client 仍可从 Session summary `cwd` 自愈派生默认路径；使用自定义 `statePath`
  的部署在这种 late-enable 场景**仍需刷新页面**，以取得 custom resolved path 与 `override:true`。
- notes 仍与 board 同生命周期、同 active lead 所有权；浏览器与人类只读，正文仍由 DSH 原生文件工具读写。
- 不新增 Host API、Remote、`dsh.client.inject` 或高版本-only 依赖。

## English summary

v0.4.3-rc.3 is the third prerelease candidate for the planned 0.4.3 release. It renames the deployment key
`boardPath` to `statePath` and changes its meaning to a workspace-relative state directory, defaulting to
`.dsh/devlead`. The board is `<workspace>/<statePath>/board.json`; notes live under
`<workspace>/<statePath>/notes/`. Migrate `boardPath: custom/board.json` to `statePath: custom`; notes follow
automatically. The old key is silently ignored as unknown, so leaving it in place selects the default state
directory rather than the old custom board. Boards outside the original workspace must be moved into it together
with their sibling `notes/` directory.

The value is a directory, not an exact board filename; blank is not a default alias. Absolute POSIX, Windows
drive and UNC paths, backslashes, empty segments and `..` escapes are rejected with `BOARD_INVALID` and
`/statePath`. The final `board.json` symlink remains forbidden, parent-directory symlinks are allowed, and a
missing workspace is never recreated. Resolution uses the lead Session's original workspace root, not a worktree
checkout. Board/notes schemas, CAS and tools are unchanged. The browser global's absolute `boardPath` field is
renamed to `boardFilePath`, and Host's `boardPathOverride` flag is renamed to `statePathOverride` on both ends.
Mixed pre-rc.3/rc.3 Host and client versions are not guaranteed to keep this global compatible. A custom
`statePath` still requires a page refresh in the late-enable case. Stage publishes nothing: maintainers must
approve only the six new `0.4.3-rc.3` records on `next` before creating the prerelease GitHub Release; `latest`
stays 0.4.2.
