# v0.4.3-rc.3 — `boardPath` 重命名为相对状态目录 `statePath`（prerelease 草稿）

这是计划中 **0.4.3** 版本的第三个 prerelease 候选说明草稿，保留 rc.1/rc.2 的全部契约变更，并追加一项

**相对状态目录**。旧键不能继续保留；升级前必须按本文迁移。

## Breaking：配置项与目录派生

`statePath` 只接受相对 active lead Session **创建时的原始 workspace 根**（`SessionHeader.cwd`，不是某次
turn 的 effective/worktree cwd）的目录。省略时默认 **`.dsh/devlead`**；空白不再表示使用默认值。

派生结果固定为：

```text
board = <workspace>/<statePath>/board.json
notes = <workspace>/<statePath>/notes/{index.json,<project>/<note-id>.md}
```

例如：

```yaml
- id: devlead
  name: '@yankeguo/dsh-devlead'
  config:
    # 保留部署需要的其他 devlead config 键；DSH 整体替换一行的 config。
    statePath: custom/state
```

对应 `<workspace>/custom/state/board.json`、`<workspace>/custom/state/notes/index.json` 与
`<workspace>/custom/state/notes/<project>/<note-id>.md`。`statePath` 只表示目录：不要传入
`custom/state/board.json` 这样的旧精确文件值（它不会再被选作 board 文件），也没有独立 notes 路径配置。

旧 `boardPath` 键只要出现就 **fail-fast**，包括空白值；不会被当作未知键忽略，也不会静默回退。错误为结构化
`BOARD_INVALID`，validation issue pointer 为 **`/statePath`**，并明确说明：

> boardPath 已重命名为 statePath，且现在是相对目录（默认 .dsh/devlead）

错误同时给出迁移操作：删除 `boardPath`，按旧文件所在目录改配 `statePath`，并确认 `board.json` 与 `notes/`
位于该状态目录。

### 路径安全与生命周期

- 只允许使用 `/` 分隔的相对目录；拒绝 POSIX 绝对路径、Windows 盘符路径与 UNC 路径。
- 拒绝反斜杠、空路径段与 `..` 逃逸（例如 `../x`、`a/../../x`）；解析结果必须仍在原始 workspace 根内。
- 最终派生的 **`board.json` 仍不能是 symlink**；状态目录及其父目录链中的 symlink 可接受。
- 默认与自定义 `statePath` 都要求原始 workspace 根仍存在且是目录。根被删除、移走或无法 `stat` 时看板保持
  disabled（`boardDisabledReason = missing-workspace`），**不会为了看板重建 workspace**。
- 配置校验失败属于 fail-fast，不属于 board start 的 degraded 路径。

## 升级步骤

### 1. 停止写入并检查旧配置

加载 rc.3 前，先 `/devlead off` 或停止相关 Host，检查并备份 profile `cordis.patch.yml` 中 loader row
`devlead` 的 `config`，以及现有 `board.json` 与同级 `notes/`。如果不需要移动文件，也必须先修改配置：
旧 `boardPath` 即使为空也会让新版本启动失败。

### 2. 删除旧键并改配状态目录

按下表迁移；右列是目录，不再带 `board.json` 文件名：

| rc.2 及更早配置 | rc.3 配置 | 说明 |
| --- | --- | --- |
| 未配置 `boardPath` | 省略 `statePath` | 使用默认 `.dsh/devlead` |
| `boardPath: ''` | 删除旧键并省略 `statePath` | 旧空白键不能保留；空白 `statePath` 也不是默认值别名 |
| `boardPath: custom/board.json` | `statePath: custom` | 文件仍位于 `<workspace>/custom/` 时无需移动 |
| `boardPath: custom/state/board.json` | `statePath: custom/state` | 文件仍位于 `<workspace>/custom/state/` 时无需移动 |

从接受绝对路径的更旧版本直接升级时，例如原始 workspace 根为 `/work/project`，把
`boardPath: /work/project/custom/board.json` 改为 `statePath: custom`。如果旧看板在 workspace 外，先把
`board.json` 与同级 `notes/` **一起**移入原始 workspace 内的目标状态目录；不能只移动 JSON，也不能配置独立
notes 路径。

### 3. 核对磁盘布局并重新加载

以 `statePath: custom/state` 为例，确认：

```text
<workspace>/custom/state/board.json
<workspace>/custom/state/notes/index.json
<workspace>/custom/state/notes/<project>/<note-id>.md
```

随后重新加载 DSH。若看到 `BOARD_INVALID` + `/statePath`，按错误提示删除旧 `boardPath` 或修正非法目录，
不要通过保留旧键、传入文件名或清空配置来绕过迁移。无需改写 `board.json` / notes 内容，也无需
`/devlead reset`。

## 保持不变的外部与内部契约

- board/notes wire schema、文件 revision、per-project board CAS、notes index CAS、读写锁与四个 board/notes
  工具的参数/结果/权限语义均不变。
- 浏览器 global 中 Host 已解析的绝对 **`boardPath`** 字段保持原名称；Host 的 **`boardPathOverride`**
  观测字段也保持原名称。只有部署配置键改名为 `statePath`。
- 页面在 lead 启用前加载时，client 仍可从 Session summary `cwd` 自愈派生默认路径；使用自定义 `statePath`
  的部署在这种 late-enable 场景**仍需刷新页面**，以取得 custom resolved path 与 `override:true`。
- notes 仍与 board 同生命周期、同 active lead 所有权；浏览器与人类只读，正文仍由 DSH 原生文件工具读写。
- rc.1 的工具迁移、rc.2 的 workspace 相对位置要求及此前 DSH 兼容结论继续适用。

## English summary

v0.4.3-rc.3 renames the deployment key `boardPath` to `statePath` and changes its meaning to a workspace-relative
state directory, defaulting to `.dsh/devlead`. The board is `<workspace>/<statePath>/board.json`; notes live under
`<workspace>/<statePath>/notes/`. The value is a directory, not an exact board filename; there is no independent
notes-path setting. Any legacy
`boardPath` key, even blank, fails fast with structured `BOARD_INVALID` and `/statePath`, with an actionable rename
and migration message. Absolute POSIX, Windows drive and UNC paths, backslashes, empty segments and `..` escapes are
rejected. The final `board.json` symlink remains forbidden, parent-directory symlinks are allowed, and a missing
workspace is never recreated. Board/notes schemas, CAS and tools are unchanged; the browser global's absolute
`boardPath` and Host's `boardPathOverride` observation field keep their names. A custom `statePath` still requires a
page refresh in the late-enable case. The development gates `pnpm verify`, `pnpm check:packages`, and patch-flow
`pnpm e2e` passed with the exact counts recorded above; install/dry-run/CI/staging checks remain pending and are not
claimed as passing.
