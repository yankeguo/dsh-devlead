# v0.4.3-rc.2 — `boardPath` 仅支持 lead workspace 相对路径（prerelease 草稿）

> 本文件是下一个 rc 的 GitHub Release 正文草稿，不代表版本已经发布、approve 或创建 GitHub Release。
> 本文档提交不构成 push、tag 或发布指令；发布仍需人类明确批准。

## Breaking：绝对 `boardPath` 会在启动时失败

从本候选开始，DevLead 核心配置 `boardPath` 的非空值**只支持相对路径**，相对于唯一 active lead
Session 创建时的原始 workspace 根（`SessionHeader.cwd`）解析，而不是某次 turn 的 effective/worktree
cwd。支持例如：

```yaml
- id: devlead
  name: '@yankeguo/dsh-devlead'
  config:
    # 保留部署需要的其他 devlead config 键。
    boardPath: custom/board.json
```

默认值不变：省略或 trim 后为空白（`''`）仍派生
`<lead SessionHeader.cwd>/.dsh/devlead/board.json`。非空 override 通过
`path.resolve(workspaceRoot, boardPath)` 解析，并断言结果仍位于该根内。

### 必须迁移的既有配置

旧版本接受绝对路径；本候选会在 Loader 校验或直接构造服务时以 `BOARD_INVALID` 和 `/boardPath`
validation issue **fail-fast**。不会静默忽略旧值，也不会回退到默认看板。错误信息会明确要求改成
“relative to the lead workspace”的路径。

若旧配置为：

```yaml
boardPath: /work/project/custom/board.json
```

且 lead 的原始 workspace 根为 `/work/project`，迁移为：

```yaml
boardPath: custom/board.json
```

不再支持把看板放在 lead 原始 workspace 之外；这种部署需要先把文件移入该 workspace，再配置相对路径。
`SessionHeader.cwd` 缺失、不是绝对路径或目录已不存在时，看板保持 disabled；相对 override 也不能
让 Host 重建已删除的 workspace。

### 路径安全规则

- 拒绝 POSIX 绝对路径（如 `/tmp/x`）、Windows 盘符路径（如 `C:\\x`、`C:/x`）与 UNC
  （如 `\\\\server\\share`）。
- 拒绝反斜杠和空路径段；使用 `/` 分隔。
- 拒绝 `..` 逃逸（如 `../x`、`a/../../x`）；解析后必须仍在原始 workspace 根内。
- 看板最终路径组件不能是 symlink；父目录链中的 symlink 规则不变。

## 不变量

- 空白配置的默认派生、原始 workspace 根与 worktree 隔离语义不变。
- notes 根仍固定为已解析 `dirname(boardPath)/notes`；notes schema、正文与 CAS 语义不变。
- board watch、notification、AI 工具参数与浏览器读写契约不变。
- 不需要迁移 `board.json` 内容，也不需要 `/devlead reset`；本次迁移只涉及部署配置及必要的文件位置调整。

## English migration summary

`boardPath` is now workspace-relative only. Blank keeps the existing
`<lead SessionHeader.cwd>/.dsh/devlead/board.json` default. Absolute POSIX, Windows drive and UNC paths
fail service loading/construction with `BOARD_INVALID` and an actionable `/boardPath` issue; there is no
silent fallback. Replace an old absolute value with a path relative to the lead's original workspace (for
example, `/work/project/custom/board.json` becomes `custom/board.json` when that workspace is
`/work/project`). Boards outside that root must be moved into it. Backslashes, empty segments and `..`
escapes are rejected, and the final component must not be a symlink. Notes derivation, watch/notification
behavior and tool semantics are unchanged.
