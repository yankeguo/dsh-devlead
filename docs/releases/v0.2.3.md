# v0.2.3 — 派发模型选择、Host 模型目录与 Agent Teams 判断

0.2.3 是 **patch 版本**，不包含 breaking change：`devlead_create_session` 新增创建时的模型选择
（`provider` + `model`，可选 `reasoning_effort`）与 `agent_teams`；新增只读
`devlead_list_models`（模型工具 11 → 12），让 lead 在 pin 之前查询真实可用路线；默认行为保持
**继承 Host 默认模型**，且从不会改写 profile 默认模型。持久记录格式、既有公开 API、
`engines.dsh`（仍为 `>=0.2.2-rc.1 <0.3.0`）、人类命令与 UI 均不变。

## 模型选择与推理强度

`devlead_create_session` 新增：

| 参数 | 说明 |
| --- | --- |
| `provider` | 可选；与 `model` 成对出现 |
| `model` | 可选；与 `provider` 成对出现 |
| `reasoning_effort` | 可选；只能与成对模型一起使用，省略时继承模型默认 effort |

口径：

- **默认继承 Host 默认模型**；只有人类明确要求，或简报确实需要成本/能力路由、可复现性时才
  指定。需要 pin 时先调用 `devlead_list_models`，不要猜 provider/model/effort。
- 创建前按与 Session controller `selectModel` 相同的口径校验（provider 已注册、model 在当前
  可用列表、`ctx.llm.resolveCallConfig` 接受 route/effort）；失败报
  `DEVLEAD_MODEL_UNAVAILABLE` 且**不创建 Session**。
- 创建后通过 `agent.model.select` 记录在子 Session 上（durable `model/selection` 事件），
  **不**走会改写 profile 默认模型的 `sessionController.selectModel` /
  `agentDefaultModel.saveSelection`；profile 默认模型前后不变。
- 两者都是 **creation-time only**；`devlead_prompt_session` 不会重新指定。

## `devlead_list_models`（11 → 12）

只读工具，返回精简的 Host 模型目录：

```json
{
  "default": { "provider": "provider-a", "model": "model-a", "reasoningEffort": "medium" },
  "routableProviders": ["provider-a"],
  "providers": [{
    "id": "provider-a",
    "name": "Provider A",
    "models": [{
      "id": "model-a",
      "name": "Model A",
      "reasoning": {
        "efforts": [{ "id": "low", "name": "Low" }],
        "defaultEffort": "low"
      }
    }]
  }],
  "failures": [{ "id": "provider-b", "name": "Provider B", "message": "catalog lookup failed" }]
}
```

省略 model description/badge 等展示字段以控制 token；provider 目录失败会如实出现在
`failures` 中。工具描述明确「大多数 dispatch 应省略模型参数、继承默认；需要 pin 时先查目录」。
Host 未组合 `sessionController` 或目录读取失败时报 `DEVLEAD_SESSION_UNAVAILABLE`。

## Agent Teams：显式 opt-in + lead 自主判断

- `agent_teams: true` 启用，`false` 显式关闭，省略则不动 Host 默认。
- 默认建议：简单线性任务省略；复杂、多步、可并行、适合子代理协作的任务，lead 可自主决定启用，
  并在汇报中说明是否开启及原因。人类明确要求开/关时照做。
- 启用通过可选 `ctx.agentTeams` 服务（durable `team/mode`），没有静态 import；Host 未组合该
  服务时，`true` 在创建前报 `DEVLEAD_TEAM_UNAVAILABLE` 且不创建 Session，`false`/省略正常。

## DSH 0.2.2-rc.1 – rc.3 兼容

| 能力 | 0.2.2-rc.1 | 0.2.2-rc.2 | 0.2.2-rc.3 | 说明 |
| --- | --- | --- | --- | --- |
| 既有工具 / `/devlead` / UI | 支持 | 支持 | 支持 | 基础插件面 |
| 模型选择 + `reasoning_effort` | 支持 | 支持 | 支持 | Session 级；不改 profile 默认 |
| `devlead_list_models` | 支持 | 支持 | 支持 | `sessionController.modelCatalog()` rc.1 已有 |
| `agent_teams: true` | **不支持** → `DEVLEAD_TEAM_UNAVAILABLE`，不创建 Session | 支持\* | 支持\* | \*Host 需组合 `agent-team`；`dsh-base` rc.2+ 默认包含 |

依据：`@deepseek-ai/dsh-agent-team` 仅从 `0.2.2-rc.2` 起发布，rc.1 的 `dsh-base` 没有对应组合
行；rc.2 与 rc.3 的 agent-team 实现相同（`isEnabled(agent)`、
`setEnabled(agent, enabled, signal?)`、durable `team/mode`）。rc.1 上 `agent_teams: true` 的
错误文案会说明该能力自 rc.2 起提供/默认组合，并建议省略该参数继续 dispatch；不要重试或阻塞。

## 已知限制

- 真实 Host 的模型正向 pin 需要 provider 凭据；隔离 E2E 使用无凭据环境，因此该 3 条检查为 SKIP，
  成功路径由单元测试覆盖。
- rc.1/rc.2 的兼容 E2E 使用 `--no-worktree`（phase 2 实验组合不属于该矩阵）；rc.3 跑全量。
