# v0.2.2 — 关闭 Workspace / Session 与判断式自主

0.2.2 是 **patch 版本**，不包含 breaking change：新增 3 个模型工具（8 → 11），让 DevLead 能
关闭（注销）Workspace、归档/恢复 Session，并把关闭授权从「必须人类逐条明确要求」放宽为
**判断式自主**；同时把只读调研收窄为**有界可行性判断**，进一步细化调研与实现随简报交给被派发
的 Session。持久记录格式、既有公开 API、`engines.dsh`、人类命令与 UI 均不变。

## 新模型工具（8 → 11）

| 工具 | 参数 | 返回（canonical JSON） |
| --- | --- | --- |
| `devlead_remove_workspace` | `workspace`（必填：id 或已注册路径） | `{ workspace, removed }`（注销前快照） |
| `devlead_archive_session` | `session`（必填）、`stop_running?`（默认 false） | `{ sessionId, archived: true, stopped }` |
| `devlead_unarchive_session` | `session`（必填） | `{ sessionId, archived: false }` |

语义沿用 DSH 自己的术语，且**都不是物理删除**：

- **remove（注销 Workspace）**：只移除 Workspace 注册记录，目录、文件与所有 Session 日志都
  保留；其 Session 变为未分组（仍可打开/续写）。重新注册同一目录会创建全新 Workspace，
  旧 Session 不会自动归入。返回值携带注销前的 Workspace 视图（含刚变为未分组的 Session ids）。
- **archive（归档 Session）**：Session 从侧边栏分组消失但日志保留，可用
  `devlead_unarchive_session` 恢复到原来的 Workspace 位置；重复归档是幂等 no-op（已归档时
  `stopped:false`，不检查活动也不请求停止）。
- **stop_running**：带运行中工作（turn / subagent / job / schedule）的 Session 默认以新增错误码
  `DEVLEAD_SESSION_ACTIVE` 拒绝；传 `stop_running: true` 时**先写归档**，再通过 Host 的
  `workspace/session-stop` providers 请求停止（与人类点停止同一路径），不等待 settle，结果
  `stopped: true`。
- **自我归档守卫**：lead 不能归档自己（`DEVLEAD_INVALID_INPUT`），避免暂停自身通知投递或取消
  当前 turn；需要人类从侧边栏操作。
- 新错误码：`DEVLEAD_SESSION_ACTIVE`（Host 的 `WorkspaceActiveSessionError` 映射；消息按种类
  列出活动，item 最多 3 条）。

## 判断式自主（close authorization）

policy 与三个工具描述从硬性「必须人类显式授权」改为**判断式自主**：当关闭确实服务任务且属于
合理收尾时，模型可自行归档自己创建/派发且已完成的临时 Session、注销明显陈旧/重复/空置或由
自己创建的 Workspace 注册，并在人类说「整理/收尾/清理」时自行判断范围。

保留的边界：

- 不关闭人类正在使用/对话的 Session 或 Workspace；
- 不用关闭掩盖失败或跳过汇报；
- 不做无关的大范围清理；
- 归档可逆、优先使用；注销影响面更大（重新注册得到全新 Workspace），只在注册本身陈旧/重复/
  空置/自己创建时自主注销；
- `stop_running` 等于主动取消运行中工作，只在确实要终止时使用；
- 每次自主关闭都要汇报关闭了什么、为什么、影响面（哪些 Session 变未分组、是否停止运行中
  工作），并说明归档可以 unarchive。

## 有界可行性判断与深挖交接

`Role boundary` 的只读调研从「为简报与审阅读代码」改为 **feasibility triage, not research**：
只读到足以判定归属、给出当前行为/目标结果的高层事实、定义验证方式，即停止并派发；明确不读完
整模块、不做完整复现/根因分析、不预先设计实现。派发简报新增**留给 Session 确认/细化的开放
问题**，允许「带开放问题的简报」；进一步细化调研与实现属于被派发的 Session。仅在归属/安全
需要、人类明确要求、或审阅需核对具体断言时继续深读。

## 审计打磨

- 统一「归档 Session」与「注销 Workspace」的措辞：清理时优先归档已完成 Session、保留
  Workspace 注册，避免把两个不同实体当成同一决策的两个选项。
- policy 常驻长度守卫改为直接度量导出的 base policy（以 0.2.1 的 7,896 字符为基线，上限
  +10%），当前 8,581 字符（+8.7%）。
- 文档化「已归档 → `stopped:false`（Host no-op）」与「`removed:false`（并发注销）」语义；
  `devlead_remove_workspace` 描述注明返回值含未分组 Session ids。
- 测试补充：注销后 `listWorkspaces` 不再包含、cold persisted Session 的 unarchive、stop 归档
  结果的运行时 schema 校验。
