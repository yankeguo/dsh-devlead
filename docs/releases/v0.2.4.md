# v0.2.4 — rc.1–rc.4 兼容、审计修复与界面打磨

0.2.4 是 **patch 版本**，不包含 breaking change：人类命令、watch / 归档 / preset 选择等产品
语义、持久记录格式、公开 API 与 `engines.dsh`（仍为 `>=0.2.2-rc.1 <0.3.0`）都不变。本版
把 DSH 兼容面从 rc.1–rc.3 扩到 **rc.1–rc.4**，修复一轮全仓审计发现的真实缺陷，并收紧
peer 依赖与 UI 可访问性。

**rc.4 无降级项。** rc.4 已发布到 npm（npm 的 `latest` tag 仍指向 rc.1，rc.4 在 `next`

rc.3→rc.4 没有 API/类型变化；rc.2→rc.3 的 `dsh-client-ui-workspace` 变化是新增
`workspace.picker` Factory，DevLead 使用的 4 个槽位在 rc.1 已存在。

## peer 依赖与安装

- 6 个包的 `@deepseek-ai/dsh-*` peer 从精确 `0.2.2-rc.1` 改为
  `>=0.2.2-rc.1 <0.3.0`；`zod` 从 `4.4.3` 改为 `^4.4.3`（DSH 自身安装的 zod 为
  `4.6.7`，旧 pin 会报 unmet peer）。
- 这**不影响 DSH 加载**：存在 `engines.dsh` 时，DSH 的 plugin compatibility 检查只按
  `engines.dsh` 判定，忽略 peers。它影响的是 profile 的 pnpm peer 检查：旧精确 pin 会在
  rc.2/rc.3/rc.4 上列出 unmet peer。改后 `pnpm peers check` 在 rc.1 与 rc.4 模拟环境均为
  “No peer dependency issues found”。
- devDependencies 仍固定 rc.1，类型检查始终面向最旧支持 API；lockfile 只增加 `semver`
  这一 devDependency（`scripts/check-packages.mjs` 用它校验“root devDependency 落在 peer
  范围内”）。

## 核心（packages/devlead）

- **冷启动扫描先排序后读标题**：`listSessions` 现在用一次 query listing 的 header 与 live
  title 排序，只对最终保留的行读 cold title（旧实现会为截断前的每个冷 Session 折完整日志）。
- **readiness 真正有界、可中断**：persistence/query 读取带 `AbortSignal` 并加 deadline race；
  插件 dispose 会清 timer、唤醒 readiness sleep，晚到的 rehydration 不再写 hub。
- **cold lead resume 有界重试**：resolve 瞬时失败（如 writer-held）最多重试 5 次，成功 live
  索引会清掉旧 timer；放弃时只 warning，不阻塞其他批次。
- **通知耐久性修正**：append 失败时通知进入 `unsaved` 而不是被当作已 durable；归档分支不再
  清掉尚未持久化的 `unsaved`；这维持了“pending = 已 durable”的不变量。
- **eager projection-cache checkpoint**：模式/watch/reset 的 durable 写入后主动
  `sessionProjectionCache.write(session)`，把“cache 落后 ≤5s + 崩溃”导致 stale-negative 行
  隐藏真实 lead 的窗口尽量缩小；cache 缺席或写失败只 warning。
- **身份解析不静默降级**：exhaustive 解析时 query listing 失败报
  `DEVLEAD_SESSION_UNAVAILABLE`，不再把 live-only 候选集当作完整集（避免前缀解析到错误
  Session）。
- **`lastTurn: 0` 哨兵不再泄漏**：无 turn 的 live Agent 现在省略 `lastTurn`，与冷 Session
  一致。
- **`listWorkspaces` 预先检查 signal**：空 registry / 空列表也会按 AbortSignal 语义拒绝。
- **rehydration 不覆盖 live 索引**：扫描期间被 resume 的 lead 由 live `syncLead` 负责，旧
  快照不会回滚它的 watch 集合。

## 工具与命令（packages/tool、packages/command）

- 工具错误映射保留原始 `cause`，便于宿主日志定位。
- `devlead_list_sessions.limit` 描述明确 watched-only 例外：为不隐藏任何被监督 Session，
  watch 集合大于 limit 时仍返回整个集合（与既有、已测试的语义一致）。
- `/devlead watch` 引号解析支持中文 IME 的弯引号/全角引号（`“”`、`‘’`、`「」`、`『』`、
  `＂＂`）；闭合引号后有多余文本时给出准确诊断，不再误报 “unmatched quote”。
- 误传完整命令行（如 `rawInput = "/devlead on"`）时提示“只传命令名之后的文本”，而不是把
  `/devlead` 当成未知子命令。
- `/devlead status` 不再出现“archived but running”自相矛盾：摘要只统计未归档的运行中
  Session，行显示 `archived (running)`。

## 客户端 UI（packages/client-ui）

- 失败提示可通过点击/触摸固定阅读（`Tooltip openOnClick` 仅在失败态启用），移除“hover to
  read”这种触屏不可达的文案；失败文案继续进入 `aria-label` 与 live region。
- 移除按钮上与 `Tooltip` 冲突的原生 `title`（不再出现双 tooltip）。
- 失败态的 hover 不再覆盖错误色；off 态文字改用 `label-secondary` 提升对比度；错误文字改用
  `label-error`；`missing` 计数改中性文字色。
- 增加 `aria-pressed` 背景反馈；状态条圆角与相邻 composer 卡片统一为 `radius-lg`。
- 窄屏（≤480px）隐藏 toggle 文本、状态条品牌名与过期计数，通知文本继续 ellipsis，避免挤压
  composer toolbar / dock。
- 移除无调用者的 `failureCopy` 与 4 条不可达 i18n key（减少约 20 行死代码）；中文提示把
  “子会话”改为“被监督会话”。

## 已知限制

- 正向模型选择 E2E 仍依赖 Host 的 provider 凭据；无凭据时如实 SKIP，不伪造。
- stale projection-cache 的崩溃窗口只能缩小、不能数学上消除：最终一致性仍依赖 cache 行，
  或依赖 lead Session 被打开后的 live 索引；eager checkpoint 把窗口缩到一次 durable 写入。
- 兼容矩阵的 rc.1–rc.3 只跑 `--no-worktree`（阶段 1 + 1b + 3）；worktree 阶段在 rc.4 的
  installed 与 patch 两条 flow 上完整通过。实验 worktree bundle 不属于任何版本的默认组合。
