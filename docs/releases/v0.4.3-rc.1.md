# v0.4.3-rc.1 — 契约收口：调度、看板持久化、工具语义与原子关闭（prerelease，dist-tag `next`）

这是计划中 **0.4.3** 版本的首个 prerelease 候选，基于已发布的稳定版 `0.4.2`。本候选把几处成熟后的契约
一次性收口：**看板改为 per-project revision/CAS**、**notes 工具只维护索引而正文归 DSH 原生文件工具**、
**看板持久化移出插件（不再调用 git）**、**关闭工具收敛为单 Session 原子语义**、**取消插件内的静态模型
路由配置**。这是 **0.x 允许的破坏性版本**，会影响既有工具调用方；磁盘上的 DevLead state、`board.json`
与 notes 索引**不需要迁移**，也不需要 `/devlead reset`。

安装时使用精确版本（发布后 24 小时内尤其不要用 `@next`，避免 pnpm `minimumReleaseAge` 回退到 npm
占位版本；详见 [PUBLISHING](../PUBLISHING.md)）：

```sh
dsh plugin --profile desktop add @yankeguo/dsh-devlead-bundle@0.4.3-rc.1
```

## 1. 收紧调度契约（`a5911c1`）

### 看板：per-project revision 与 CAS

`board.json` 的每个 project 现在带自己的 `revision`，代表**最近一次改动该 project 的 board 代际**。
`devlead_board_update` 的 `expected_revision` 只校验目标 project 的 revision（不存在的 project 视为 `0`，
`create:true` 时可用 `expected_revision:0` 抢占创建），因此并发更新**其它** project 不再造成假冲突。
文件级 `revision` 仍是整份看板的单调计数，每次实际写入 `+1`；结果同时返回文件级 `revision` 与
`project.revision`。

旧文件（project 没有 `revision`）在首次 Host 读取时按文件级 revision 回填，文件级 revision 不变；回填是
一次**真正的写入**：在与更新相同的跨进程 writer lock 内重读并原子替换，避免覆盖并发更新。回填只在检测到
缺失字段时发生一次，之后磁盘上每个 project 都有显式 revision。

### notes：工具只维护索引，正文归 DSH 原生 read/write/edit

- `devlead_board_note_read` **不再返回 Markdown 正文**：省略 `note` 返回项目 metadata 列表，指定 `note`
  返回单条 metadata（含 `absolutePath`、`bytes`、索引内 title/summary 与文件 live `updatedAt`），
  结果中不再有 `content` 与 `truncated`。
- `devlead_board_note_write` 的 `create` **不再接受 `content`**：只创建 metadata 与**空正文文件**；
  `update-metadata` 只改 title/summary；`delete` 先提交索引再 best-effort 删正文。`expected_revision`
  仍保护 index 写入。
- 所有正文读写都必须用 DSH 原生 `read` / `write` / `edit` 操作返回的 `absolutePath`，工具不再是第二条
  正文写入路径，也**不接受**任何文件路径输入。
- Host 的 read/list 惰性对账改为**只 stat 正文**：在 index writer lock 内比较文件大小与 mtime，必要时
  原子提交 `bytes`/`updatedAt` 修复，**不读取、不重写正文**；缺失或超 256 KiB 仍返回结构化错误且不动
  index。原先“单 note 模型结果 64 KiB 截断”的路径随正文移出工具而删除，256 KiB 存储上限与浏览器完整
  读取不变。

### wake 摘要上限与长报告交接

- notification 的 assistant `summary` 与 `devlead_get_session` 的 `lastAssistant` 默认保留 **4096 个
  Unicode 码点**，并分别带 `summaryTruncated` / `lastAssistantTruncated` 截断标记；`error`/title 仍是
  独立的 240 码点单行字段。
- `devlead_get_session` 新增可选 `last_assistant_limit`（正整数码点数），可覆盖默认预算；非法值返回
  `DEVLEAD_INVALID_INPUT`。
- wake 文本（notification / review / question / report 各 lane 的 header 载荷）统一限制在 **8000 码点**
  （超长时截断并附 “call devlead_notifications / devlead_get_session” 引导），一条超长子会话不会把唤醒
  正文撑爆。
- 长报告的标准交接方式：子 Session 把完整报告写 `/tmp/*.md`，回复里只带摘要与路径；lead 用
  `devlead_get_session` 或读文件按需取全文。

### lead 主动 interrupt 不再报 failure

`devlead_prompt_session(interrupt:true)` 由本 lead 主动停止的子 turn，仍保留真实的
`aborted`/`interrupted` transition，但 Host 会把它标记为 `cancelledByLeadInterrupt:true`，按普通活动走
**T1 `[DEV LEAD NOTIFICATION]`** followup（行内显示 `cancelled by your interrupt`），**不再**触发
`[DEV LEAD REVIEW REQUIRED]` review lane。真正的 turn 失败、外部中断、blocked/max-tokens 仍走 T2。
该标记随 durable notification 折叠持久化，cold 重投/重试不会重新升级成 review。若 stop 实际上没有发出
（目标本已 idle/cold）或 stop 调用失败，标记会被清除，不会误标后续真实失败。

## 2. 看板持久化移出插件（`e0efddc`）

`devlead_board_update` 删除 `commit` 参数；插件**不再调用 git**、不再提供 `commitBoard` 之类的提交行为。
看板文件就是普通磁盘文件：是否提交、什么时候提交，由使用该工作目录的人类/仓库流程决定，插件只负责
schema 校验、锁、CAS 与原子写。随之删除 `board-commit.ts`、service 上的提交入口与两个提交测试；文档
（[BOARD](../BOARD.md)、README、DESIGN、tool README）同步该边界。

## 3. 工具面按语义定型（`b9358b6`）

删除 tool 测试中按字符数锁定 description 体积的“prompt 预算”断言；工具面契约改由**精确清单**保证：
e2e 用 `ctx.tools.resolve` 断言模式开启时恰好是 17 个主 `devlead_*` 工具、关闭时为 0、watched 子会话
恰好 1 个 `devlead_report`。描述文本仍需要 review，但不再作为一个脆弱的字节预算测试。

## 4. archive 恢复原子语义（`7a1b1e9`）

- `devlead_archive_session` 一次只处理**一个** Session：`archived:true`（默认）归档，`archived:false`
  恢复。批量 `sessions` 参数已删除；多个 Session 用 PTC `run_code` 循环或并行调用，不另设批量 API。
- `devlead_unarchive_session` 工具**已删除**；恢复改用 `devlead_archive_session` 的 `archived:false`。
  结果统一为单个对象：归档 `{ sessionId, archived: true, stopped, watched }`，恢复
  `{ sessionId, archived: false }`。
- 归档成功（含本就已归档的幂等调用）会**自动把该 Session 从本 lead 的 watch 集合移除**，结果带
  `watched:false`；顺序是先提交归档、再 unwatch，unwatch/flush 失败会如实报错但**不回滚**已提交的归档。
- `archived:false` 与 `stop_running:true` 同时传是非法组合，返回结构化 `DEVLEAD_INVALID_INPUT`。
- core service 仍保留 `unarchiveSession()` 作为内部/工具转发入口，破坏面只在模型工具与工具输出。

## 5. 移除静态模型路由（`22988ad`）

删除插件配置 `workspaceModels` 与 `defaultModel`，以及 protocol 的
`DevLeadWorkspaceModelSelection` 类型。`devlead_create_session` 省略 `provider`/`model` 时**直接继承
Host 默认模型**，不再有“按 resolved Workspace id/path/title 匹配静态路由再回退 defaultModel”的隐式行为；
显式传参的能力与校验完全保留：`provider`/`model` 必须成对，`reasoning_effort` 只能与成对模型一起用，
创建前仍按 Session controller `selectModel` 的口径校验可用性（不可用返回 `DEVLEAD_MODEL_UNAVAILABLE`
且不创建 Session），结果只带实际显式应用的 `model` / `agentTeams`。

旧 profile 的 `cordis.patch.yml` 里残留这两个键不会让插件加载失败（loader 会忽略未声明键），但建议删除，
避免误以为仍在生效。

## Breaking changes（0.x 允许，调用方必须迁移）

| # | 变更 | 旧行为 | 新行为 |
| --- | --- | --- | --- |
| 1 | `devlead_board_note_read` 结果 | 指定 `note` 时返回 Markdown `content`（可能被 64 KiB 截断） | 只返回 metadata（含 `absolutePath`）；正文用 DSH 原生 `read` 读该路径 |
| 2 | `devlead_board_note_write` 的 `create` | 接受可选 `content` 作为初始正文 | 不接受 `content`；只创建空文件，正文随后用原生 `write`/`edit` |
| 3 | `devlead_archive_session` 参数与输出 | `sessions` 批量参数；输出按集合/数组表达 | 单 `session` + `archived?`；输出单个对象 `{ sessionId, archived, stopped?, watched? }` |
| 4 | `devlead_unarchive_session` | 独立工具 | **已删除**；改用 `devlead_archive_session(archived:false)` |
| 5 | `devlead_board_update` 的 `commit` | 可选，插件内调用 git 提交看板 | **已删除**；插件不再调用 git |
| 6 | `devlead_board_update.expected_revision` 语义 | 校验整份看板的文件级 revision | 只校验目标 project 的 `project.revision`；旧调用方若把文件级 revision 直接传入，可能得到 `BOARD_REVISION_CONFLICT`，应先 `devlead_board_read` 取该 project 的 revision |
| 7 | 工具数量 | 18 个主工具 + 1 个 `devlead_report`（共 19） | **17 个主工具** + 1 个 `devlead_report`（共 **18**） |
| 8 | 配置 `workspaceModels` / `defaultModel` | 可选静态路由 | 已删除；省略模型参数直接继承 Host 默认 |

未声明的参数会被 `assertKnownArguments` 明确拒绝（报 “unknown argument ...” 并列出可接受参数），所以旧的
批量/`content`/`commit` 调用会**显式失败**而不是被静默忽略。

**非破坏的新增**：`devlead_get_session.last_assistant_limit`；notification 的 `summaryTruncated` /
`cancelledByLeadInterrupt`、session view 的 `lastAssistantTruncated`、archive 结果的 `watched`
（都是可选字段，旧记录/旧 projection 解码不受影响）。

## 升级与兼容

- **不需要数据迁移，也不需要 `/devlead reset`**：durable mode/watch/outbox/notification/question 记录
  格式不变，新字段全部可选；旧 `board.json` 的 project revision 在首次 Host 读取时自动回填（文件级
  revision 不变），notes 索引 schema 不变、既有正文文件保持有效。
- 工具调用方按上表迁移：notes 正文改用 `absolutePath` + 原生文件工具；恢复改用
  `archive_session(archived:false)`；去掉 `commit`/`sessions`/`content`；CAS 用 project revision。
- 删除 profile 配置里的 `workspaceModels` / `defaultModel`；需要固定模型时在
  `devlead_create_session` 显式传 `provider`/`model`。
- DSH 兼容面保持 **`0.2.2-rc.1` – `0.2.2-rc.5`**，`engines.dsh` 保持 **`>=0.2.2-rc.1 <0.3.0`**；
  不新增 `dsh.client.inject`、Remote、Host API 或高版本-only 依赖。
- 本候选不改 client-ui 视觉：看板/notes 面板、轮询、KPI、侧栏标记行为照旧；变化只在 Host 数据层、
  工具契约与 prompt/policy 文案。

## 发布方式：stage → 人工 approve → GitHub Release

1. 人类明确批准后，推送指向最终 release commit 的 annotated tag `v0.4.3-rc.1`。CI 使用 OIDC trusted
   publishing，以 npm **`next`** dist-tag **stage** 全部 6 个包并生成 provenance；**stage 不公开任何内容**。
2. 维护者在 npmjs.com 网页核对本次 CI 的 6 条 staged 记录：版本必须全部为 `0.4.3-rc.1`、dist-tag 必须为
   `next`，然后人工批量 approve。approve 即公开且不可撤销；approve 后 `next` 指向本候选，`latest` 仍为
   **0.4.2**。历史上 `0.4.2-rc.1`、`0.4.2-rc.4`、`0.4.2-rc.8` 的 staged 记录从未 approve，不得混入本次批准。
3. approve 完成并核对 dist-tags 后，使用既有 tag 和本文件手动创建 prerelease GitHub Release：

   ```sh
   gh release create v0.4.3-rc.1 --repo yankeguo/dsh-devlead --title v0.4.3-rc.1 \
     --notes-file docs/releases/v0.4.3-rc.1.md --verify-tag --prerelease --latest=false
   ```

4. 最后做三方核对：6 个包的 `@0.4.3-rc.1` 在 npm 可见、`dist-tags.next = 0.4.3-rc.1`、
   `dist-tags.latest = 0.4.2`；GitHub Release 指向 tag `v0.4.3-rc.1` 与同一 commit，
   `isPrerelease=true`、`isLatest=false`、`isDraft=false`。

## English summary

v0.4.3-rc.1 is the first prerelease candidate for the planned 0.4.3 minor release, built on the published 0.4.2
stable. It is an intentional 0.x breaking contract cleanup. The project board now keeps a per-project revision and
CASes only the target project (legacy files are backfilled once under the writer lock on first Host read). Notes
tools own metadata only: the read tool returns metadata plus `absolutePath`, create makes an empty body, and every
Markdown body read/edit goes through DSH-native read/write/edit; Host read/list reconciliation now stats bodies
without reading or rewriting them. Assistant excerpts grow to 4096 code points with explicit truncation state, a
`last_assistant_limit` override exists, and every wake payload is bounded to 8000 code points. A child turn that
this lead cancelled through `interrupt:true` keeps its real transition but is delivered as ordinary T1 activity with
`cancelledByLeadInterrupt` instead of a review wake. Board persistence no longer calls git: `devlead_board_update`
drops `commit`. The archive tool is now one atomic Session operation (`archived:false` restores, successful archives
auto-unwatch), the batch `sessions` parameter and the separate `devlead_unarchive_session` tool are gone, and the
tool surface is 17 main tools + `devlead_report` (18 total). Static `workspaceModels`/`defaultModel` routing is
removed: omitting model arguments inherits the Host default, while explicit provider/model selection keeps its
validation. No state migration or `/devlead reset` is needed; DSH `0.2.2-rc.1`–`0.2.2-rc.5` compatibility and
`engines.dsh` are unchanged. Stage publishes nothing: maintainers must approve only the six new `0.4.3-rc.1`
records on `next` before creating the prerelease GitHub Release; `latest` stays 0.4.2.
